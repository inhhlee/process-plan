이 계획은 프로젝트의 과제5를 완료하기 위한 목표·작업 순서·산출물·확인 기준을 정리한다. 계획과 예상 결과를 작성한 상태이며 이 과제의 실제 구현·시험 결과는 이 문서에서 아직 확인하지 않았다. 기존 코드의 재사용 범위는 착수 전에 대조한다. 아래 작업 순서와 시험 항목은 요구사항·공통 규칙·데이터·기능명세를 기준으로 제안한 초기 계획이다.

## 2. 배경과 목적

과제1~4의 구성요소와 SQLite를 연결하여 가상 AMR 기반 기초 관제 시스템 실행본을 구성하고, 전체 경로의 동작을 시나리오로 검증한다.

## 3. 용어 설명

| 용어 | 쉬운 설명 |
| --- | --- |
| 통합 검증 | 각 모듈을 실제로 연결한 전체 경로의 동작을 확인하는 시험이다. |
| 시나리오 | 입력·조건·절차와 예상 결과를 정하여 반복할 수 있게 만든 시험 흐름이다. |
| 계약 버전 | 연결한 모듈이 공통으로 적용한 데이터·메시지·인터페이스 정의의 판이다. |
| 재현 절차 | 다른 사람이 같은 설정과 순서로 시험을 다시 수행할 수 있게 남기는 방법이다. |
| ACK / History | 명령에 대한 응답과 업무 이력이다. 요청부터 응답·표시·저장까지 연결해서 확인한다. |

## 7. 완료 기준

### 과제 전체 완료 체크

- [ ] 과제1~4와 SQLite가 연결된 기초 관제 시스템 실행본을 제공한다.
- [ ] 정상 운행·명령·알람·통신 이상 시나리오를 실제로 수행한다.
- [ ] 설정·계약 버전·실행 순서·예상 결과·실제 결과·판정을 기록한다.
- [ ] 실패한 시험은 해결·재시험 결과 또는 미해결 영향 범위를 명시한다.
- [ ] 실행본과 재현 절차를 연결하고 검증 결과를 근거로 완료 여부를 판단한다.

위 체크는 실제 결과를 확인한 뒤 표시한다. 계획 초안 작성 완료와 과제 개발 완료를 구분한다.

실행 후에는 사용 설정·계약 버전, 입력, 절차, 예상 결과, 실제 결과, 판정 및 Log·화면·DB 등 근거를 검증 결과에 작성한다. 미정 정책에 의존하는 시험은 해당 결정 항목과 적용 값을 함께 기록한다.

### 이번 작업 시험

이번 작업은 미선정이며 아래 항목은 착수 전에 작성한다. 전체 시험 계획에서 선택한 범위를 구체화하며, 실제 결과는 실행별 검증결과에 기록한다.

| 시험 ID | 입력·조건 | 성공 기준 | 실패 판단 |
| --- | --- | --- | --- |
| 미선정 — 작업 선택 후 부여 | 미작성 — 실제 입력·조건 작성 | 미작성 — 관찰 가능한 결과 작성 | 미작성 — 실패로 판단할 결과 작성 |

### 상세 실행 절차

미작성 — 이번 작업 선택 후 실행 환경·명령·순서·관찰 조건·기록 위치를 착수 전에 작성한다. 실제 시험 결과는 [검증결과 빈 양식](../../기준/양식/검증결과.md)을 사용해 이 과제의 `산출물/`에 남긴다.
