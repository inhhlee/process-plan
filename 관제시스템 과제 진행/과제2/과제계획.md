이 계획은 프로젝트의 과제2를 완료하기 위한 목표·작업 순서·산출물·확인 기준을 정리한다. 계획과 예상 결과를 작성한 상태이며 이 과제의 실제 구현·시험 결과는 이 문서에서 아직 확인하지 않았다. 기존 코드의 재사용 범위는 착수 전에 대조한다. 아래 작업 순서와 시험 항목은 요구사항·공통 규칙·데이터·기능명세를 기준으로 제안한 초기 계획이다.

## 2. 배경과 목적

이동·상태 변경·알람 발생·명령 응답을 제공하는 독립 시뮬레이터를 구성하고, 수량·초기 좌표·속도·이동 경로·장애 시나리오를 설정 파일로 바꾸어 시험할 수 있도록 한다.

## 3. 용어 설명

| 용어 | 쉬운 설명 |
| --- | --- |
| 가상 AMR | 실제 로봇 대신 위치·상태·알람·명령 응답을 만들어 주는 시험 프로그램이다. |
| Telemetry | AMR의 위치·속도·상태 등 현재 정보를 전달하는 데이터다. |
| State / Alarm | 운행 상태와 장애 알림이다. 상태 변화와 알람의 관계는 D-05에서 정한다. |
| Command / ACK | AMR에 보내는 동작 요청과 응답이다. 명령과 응답은 같은 요청 ID로 연결한다. |
| 시나리오 설정 | 수량·초기 좌표·속도·경로·장애 조건을 코드 수정 없이 바꾸기 위한 입력이다. |

## 6. 개발 로드맵

### 선행 조건과 단계 흐름

> 단계 흐름: 설정·계약 확인 → AMR 생성 → 이동·상태·알람 → ACK·데이터 송신 → 독립 시험·정리

### 전체 작업 순서

이 계획의 개발 상태는 미착수로 유지하며 작업별 예정 기한은 미정이다. 기존 코드의 해당 과제 적용 범위를 확인한 뒤 실제 상태를 갱신한다. 필요한 설계 결정부터 정리하고 결정 내용을 적용한 버전으로 시험한다.

| 순서 | 관련 항목 | 수행할 작업 | 완료 확인 조건 |
| --- | --- | --- | --- |
| 1 | AMR-01 | D-02·D-12의 설정 항목·형식·오류 처리를 정리한다. | 원문의 수량·초기 좌표·속도·경로·장애 조건이 설정에 포함된다. |
| 2 | AMR-01 | 설정 로드와 AMR별 초기 상태 생성을 구현한다. | 설정 변경이 코드 수정 없이 생성 결과에 반영된다. |
| 3 | AMR-02 | D-05의 State·Alarm·명령 허용표와 D-02의 위치 기준을 작성한다. | MOVE·STOP·RESET의 수행·거부 조건과 예상 결과가 구분된다. |
| 4 | AMR-02, AMR-03 | 이동·정지·복구 및 설정된 장애 발생·해제를 구현한다. | 위치·상태·알람이 결정한 조건대로 변한다. |
| 5 | AMR-04 | D-07의 의미로 CommandId를 보존하는 ACK를 생성한다. | 정상·거부·실패의 응답이 원래 요청에 연결된다. |
| 6 | AMR-05 | 공통 계약으로 Telemetry·Alarm·Heartbeat·ACK를 생성·송신한다. | 각 메시지가 COM-04의 계약 검증을 통과한다. |
| 7 | AMR-01~05 | 독립 실행과 설정 변경·명령·장애 시험 결과를 정리한다. | 사용 설정, 예상·실제 상태와 메시지를 근거로 남긴다. |

## 7. 완료 기준

### 과제 전체 완료 체크

- [ ] 시뮬레이터를 독립 실행할 수 있다.
- [ ] 원문의 다섯 설정 항목을 파일로 바꾸어 결과를 확인한다.
- [ ] 이동·상태·알람·명령 응답 기능을 실제 시험한다.
- [ ] 동작·거부·복구 기준과 사용 설정·계약 버전을 기록한다.
- [ ] 생성 메시지와 상태 변화의 실제 결과·판정을 남긴다.

위 체크는 실제 결과를 확인한 뒤 표시한다. 계획 초안 작성 완료와 과제 개발 완료를 구분한다.
