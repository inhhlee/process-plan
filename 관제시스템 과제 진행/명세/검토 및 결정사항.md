### D-08 재접속과 복구

- 현재 근거와 문제: 재접속은 원문 요구이다. 간격·횟수·Backoff·재구독·대기 중 명령 처리는 미정이다.
- 후속 작업과 선택 범위: 복구 시 구독 목록, 재시도 조건, 실패 표시, 대기 명령 폐기·보류·재전송 여부를 결정한다.
- 영향 기능: [COM-03](기능명세.md#com-03-broker-연결-상태-감시), [COM-06](기능명세.md#com-06-재접속과-구독-복구), [CORE-04](기능명세.md#core-04-command-요청과-결과-관리), [INT-04](기능명세.md#int-04-통신-이상과-복구-검증)
- 결정 상태: 미정

2026-10-05 확인: 현재 문서는 COM-06을 과제1 범위에 포함하지만 코드 추적기는 COM-01~05를 관리하고 DN-04는 자동 재접속을 후속 INT-04로 미룬다. 이 범위 차이는 COM-06 착수 전 또는 과제1 전체 완료 판정 전에 맞춘다. 이번 정상 Heartbeat 시험에서는 장애 복구를 다루지 않으며, 이 차이를 모든 코딩의 선행 차단 항목으로 삼지 않는다.

2026-10-06 연결 정리: [과제 대응표의 개발 순서 절](<C:/practice/docs/full/assignment_mapping.md>)에는 정상 화면 시연을 먼저 하고 자동 재접속을 2차에 수행하는 기존 사용자 선택이 기록돼 있다. 문서의 COM-06은 **과제1 최종 산출물**, 코드의 INT-04는 **복구 통합 검증 연결**로 구분하여 요구를 유지한다. 명시적 재접속·프로세스 재시작 증거만으로 자동 복구를 완료 처리하지 않는다. 구현 착수 시 추적 항목·의존성·검증 근거를 연결하고, 사수의 납품 순서 변경 승인 여부는 별도로 확인한다. 이번 문서 정리에서 개발 순서를 새로 선택하거나 승인하지 않는다.

- 영향 기능: [COM-02](기능명세.md#com-02-개별-amr-heartbeat-감시)~03, [AMR-05](기능명세.md#amr-05-시뮬레이션-데이터-생성과-송신), [CORE-02](기능명세.md#core-02-최신-상태-관리), [GUI-01](기능명세.md#gui-01-대시보드), [INT-04](기능명세.md#int-04-통신-이상과-복구-검증)
- 결정 상태: DN-10의 감시 담당·수신 시각·경계·복구 조건을 개발용 임시 채택으로 적용. 최종 Offline·운행 상태·등록 전 장비·운영 주기·Ping/Pong은 미정

2026-10-06 대조: [DN-10](<C:/practice/feature_list.json>)과 [감시 계약](<C:/practice/src/Amr.Communication/Monitoring/CONTRACT.md>)은 Communication에서 첫 정상 Heartbeat를 받은 AMR부터 감시하도록 채택했다. 기본 Timeout 5초·확인 주기 0.5초, 경과 시간 `>= Timeout`에서 중단 구간당 한 번 통지하고 정상 수신 재개 시 한 번 복구를 통지한다. 불량 입력·다른 메시지는 갱신하지 않으며 정상 Heartbeat는 Core 큐가 가득 차도 수신 시각을 갱신한다. Broker 단절 감지·종료 때 감시를 중단하고 명시적 재접속은 새 세션으로 시작한다. 최종 업무 Offline/FAULT 판단은 후속이다.

기존 시험 발행자의 약 1초 간격은 시험 입력 간격이며 Timeout·감시 확인 주기와 다르다. 기존 구현·증거를 먼저 활용하고 이 정책을 다시 미정으로 되돌리지 않는다. 실제 실행 판정은 과제계획에 연결한 기존 증거와 새 실행을 구분한다.
