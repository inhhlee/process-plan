## 1. 결정 항목과 후속 작업

<a id="task2-first-run-decisions"></a>

**2026-10-20 과제2 첫 실행본 결정 근거**

- 결정 주체·근거: 사용자가 이 대화에서 제시한 설정 필수값·오류 처리, 이동·도착 기준, 이동 중·도착 상태의 수정안을 검토한 뒤 “그 수정안대로 과제계획과 관련 명세에 반영해줘. HTML 보기본도 갱신하고 코드 구현은 아직 하지 마.”라고 요청했다.
- 근거 구분·적용 범위: 원문 R-02·R-03을 구체화한 설계 제안을 사용자 승인으로 채택했다. 아래 D-02·D-05·D-12의 확정은 [AMR2-A 첫 실행본](../과제2/과제계획.md#task2-first-run)에 한정하며 운영 정책 전체를 확정하지 않는다.
- 상세 담당: 필수 항목·단위·허용값은 [공통데이터명세](공통데이터명세.md#task2-first-run-contract), 처리·출력은 [기능명세 AMR-01~02](기능명세.md#amr-01-설정-로드와-amr-생성), 작업·시험은 [과제2 계획](../과제2/과제계획.md#task2-first-run)에서 관리한다. 이번 반영은 문서 작업이며 코드 구현·실행 검증은 수행하지 않는다.

<a id="task2-review-followup"></a>

**2026-10-21 첫 실행본 검토 보완 결정**

- 결정 주체·근거: 사용자가 이 대화의 직전 검토에서 제시한 네 보완사항을 반영하도록 요청했다. 기존 통신 계약과 ID 검사 기준 연결, AMR-01 입력 목록의 위치 갱신 주기 추가, 경과 시간 예외 처리와 대각선·비유한 속도 시험을 승인한 범위로 반영한다.
- 추가 선택·채택 이유: 경과 시간 0초는 유효한 입력으로 보아 위치·State·현재 속도를 유지한다. 음수·유한하지 않은 값을 자동 보정하면 잘못된 입력이 숨겨지므로 계산 전에 거부하고 기존 상태를 보존한다. 구체적인 입력 기준·처리는 [데이터명세](공통데이터명세.md#task2-motion-data)와 [AMR-02](기능명세.md#amr-02-command-수신과-동작-수행)를 따른다.
- 적용 범위·후속 작업: [AMR2-A 첫 실행본](../과제2/과제계획.md#task2-first-run)의 문서·예정 시험 보완이다. 기존 ID와 2026-10-20에 정한 단위·도착·최소 상태를 유지하며 코드 구현·제품 시험은 수행하지 않는다. 실제 결과는 후속 구현·검증 단계에서 기록한다.

이 항목들은 구현 전에 필요한 범위부터 검토한다. 원문에 있는 기능을 유지하면서 상세 정책을 선택한다. 제안은 현재 결정으로 간주하지 않으며 관련 과제계획에 후속 작업을 연결한다.

**2026-10-21 추가 승인 — 격자 지도에서 다익스트라·A* 비교 (D-02·D-11·D-12)**

- 결정 주체·근거: 사용자가 피드백으로 단일 AMR의 2D 최단 경로 탐색을 전달하고 격자·장애물을 선택했다. 이어 "그 제안대로 격자 지도·고정 장애물·상하좌우 4방향 이동에서 다익스트라와 A*를 비교하는 범위를 기존 명세와 과제계획에 반영해줘. 완료조건과 시험 계획도 정리하고, 코드 구현은 아직 하지 마."라고 요청했다.
- 채택: 단일 AMR·정적 격자·고정 통행 불가 셀·4방향·동일 한 칸 거리, 다익스트라와 맨해튼 휴리스틱 A*의 최단거리·탐색 확정 셀 수·계산 시간 비교. 선택한 결과를 기존 #33 이동 계산·실행 루프에 연결하고 2D 지도에 탐색 결과와 실제 이동을 표시한다. 기존 #33의 완료조건에는 소급하지 않는다.
- 문서에서 구체화한 실습 기준: 셀 중심·단위·경로/NoPath/거리0·비교 측정은 [데이터 5절](공통데이터명세.md#grid-pathfinding-data), 동작·수명은 [AMR-02](기능명세.md#grid-pathfinding-behavior), 완료조건·예정 입력은 [과제2 계획](../과제2/과제계획.md#grid-pathfinding-work), 표시 연결은 [과제3 계획](../과제3/과제계획.md#grid-pathfinding-view-work)을 원본으로 삼는다. 전체 운영 Map 정책으로 확대하지 않는다.
- 채택 이유·대안: 다익스트라로 누적 거리 기준을 확인하고 A*의 목적지 방향 추정에 따른 탐색 차이를 비교한다. 동일 간선 거리에서는 BFS도 최단 이동 횟수를 구할 수 있지만 이번 제품 비교 대상은 승인한 두 알고리즘이다. 8방향 이동은 거리·휴리스틱·모서리 통과 규칙이 달라지고 가중 지형은 최소거리와 최소비용을 구분해야 하므로 이번 범위에 넣지 않는다.
- 유지할 조건·성능 한계: 두 알고리즘에 동일한 불변 입력·독립 탐색 상태를 사용한다. 같은 최단거리라도 경로 모양은 다를 수 있다. 알고리즘의 큐·방문/부모 상태 저장 비용은 구현 후 측정하며 이번 문서 작업에서 속도·메모리 우위를 검증하지 않았다. A*의 일관된 성능 우위를 합격조건으로 두지 않는다.
- 후속 결정: 파일 스키마·실행/UI 입력 방식·지도 최대 크기/메모리 상한·동률 처리·반복 측정 횟수는 구현 착수 시 기존 코드·환경을 확인해 기록한다. 운영 좌표 원점, 로봇 크기·안전 여유, 동적 장애물·재탐색·다중 AMR은 별도 요구 단계에서 검토한다. 이미 승인한 격자·고정 장애물·4방향·두 알고리즘 범위는 다시 미정으로 취급하지 않는다.
- 결정 상태: 위 범위는 사용자 승인으로 확정, 나머지 상세는 후속. 이번 수행은 원본 명세·계획·HTML·업무 기록 갱신이며 코드 구현·제품 빌드/시험·서비스 실행·Issue/PR 생성·커밋/푸시는 하지 않는다.

### D-05 State·Alarm·명령 전환

- 현재 근거와 문제: IDLE/BUSY/STOPPED/FAULT 및 MOVE/STOP/RESET은 기존 후보이다. STOPPED 재출발, Alarm 해제와 RESET, STOP 허용 상태가 불명확하다.
- 선택지·영향: 경로 도착을 IDLE 또는 STOPPED로 표현할 수 있다. STOPPED를 도착에도 사용하면 이후 명령 정지와 구분할 추가 기준이 필요하므로 첫 실행본은 IDLE로 돌아오는 방식을 채택한다.
- 채택 내용: 초기 생성 IDLE → 이동 중 BUSY → 최종 도착 IDLE을 적용하고, 실제 이동이 없는 경로는 IDLE로 완료한다. 상태별 현재 속도는 [데이터명세](공통데이터명세.md#task2-state-data), 처리·로그는 [AMR-02](기능명세.md#amr-02-command-수신과-동작-수행)를 따른다.
- 후속 작업과 선택 범위: 첫 실행본의 최소 전이를 예정 시험에 연결한다. 전체 명령 허용표·STOPPED 재출발·RESET 및 Alarm 발생·해제·중복·재발생·복구 전이는 해당 후속 기능 구현 전에 정한다.
- 영향 기능: [AMR-02](기능명세.md#amr-02-command-수신과-동작-수행)~04, [CORE-03](기능명세.md#core-03-수신-alarm-관리)~04, [GUI-04](기능명세.md#gui-04-amr-상세와-command-요청), [INT-02](기능명세.md#int-02-command-전체-흐름-검증)~03
- 결정 상태: 첫 실행본의 자동 경로 이동 전후 상태는 [2026-10-20 승인](#task2-first-run-decisions)으로 확정. 명령별 최종 응답 시점과 STOP으로 진행 중 MOVE를 중단한 결과의 분리는 [2026-10-22 후속 승인](#provider-ack-decisions)으로 추가 확정. 전체 허용표·장애/복구 전이·RESET 복구 조건은 미정.

이번 문서 정정은 기존 채택 기록에 근거하므로 새 정책 선택이 필요하지 않다. [과제1 계획](../과제1/과제계획.md#com01-work)에는 기존 통과 범위와 후속 작업을 연결하고 HB-01~06은 필요 시 선택하는 회귀 절차로 보존한다. 기존 증거의 계약·revision·코드 영향부터 확인하며, 미실행인 문서용 HB 시험 때문에 현재 제품 기능을 임의로 실패·미착수로 되돌리지 않는다.

### 코드와 문서의 후속 정리

- 2026-10-05의 코드 요약/S015 불일치 지적은 당시 이력이다. 2026-10-06 현재 README·진행 로그·추적기를 다시 대조하여 COM-01 revision 4·COM-02 revision 2·COM-03 revision 2·COM-04 revision 4의 passing과 COM-05 revision 1의 not_started를 확인했다. 현재 코드 요약을 다시 고칠 항목으로 남기지 않는다. 상세 상태·증거는 [과제1 계획](../과제1/과제계획.md#com01-work)에서 연결한다.
- 최신 기능 상태는 코드 추적기, 과제 전체의 계획 범위는 현재 과제계획에서 확인한다. 같은 기능 ID라도 계약·범위 차이는 위 D 항목에 근거를 남기고 조정한다.

- 2026-10-06 앞선 문서 상태 정리: [요구사항정의](요구사항정의.md)·[공통규칙](공통규칙.md)의 ‘과제 1~5 모두 미착수’와 [기능명세](기능명세.md)의 ‘각 기능 개발 미착수’가 [과제1 계획](../과제1/과제계획.md)·[2026-10-05 검증결과](../과제1/산출물/2026-10-05_개발환경_검증결과.md)의 부분 구현·환경 검증 기록과 달랐다. 사용자의 전체 보완 요청에 따라 해당 상태를 담당 일정·계획·검증결과로 참조하도록 정리했다. 당시 내역은 [일일업무](../../일일업무/2026-10-06.md#document-links)에 보존한다. 이후 이번 기준 정리에서 코드 요약 불일치 지적을 갱신하고 COM-06 요구와 기존 개발 순서를 연결했다.
