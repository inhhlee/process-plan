이 계획은 프로젝트의 과제3을 완료하기 위한 목표·작업 순서·산출물·확인 기준을 정리한다. 계획과 예상 결과를 작성한 상태이며 이 과제의 실제 구현·시험 결과는 이 문서에서 아직 확인하지 않았다. 기존 코드의 재사용 범위는 착수 전에 대조한다. 아래 작업 순서와 시험 항목은 요구사항·공통 규칙·데이터·기능명세를 기준으로 제안한 초기 계획이다.

2배경과 목적

공통 명세를 기반으로 Dashboard·Map·Alarm·History·Command 화면을 구성하고, Mock AMR로 독립 실행 가능한 GUI와 DataProvider 인터페이스를 제공한다.

3용어 설명

용어 쉬운 설명
GUI 사용자가 상태를 확인하고 명령을 입력하는 화면이다.
Mock 실제 AMR·Core 대신 정해진 시험 데이터를 제공하는 대체 구현이다.
DataProvider 화면에 데이터를 주고 명령 요청을 받는 공통 접점이다. 상세 계약은 D-11에서 정한다.
Map / Marker 장비 위치를 보여 주는 지도 영역과 장비를 나타내는 표시다.
History 과거 이벤트를 조회하는 정보다. 현재 상태나 현재 알람과 구분한다.

포함하는 기능

기능 ID 기능명 제공할 동작

GUI-02 Map View와 선택 AMR 정보 2D 위치와 선택 장비의 최신 상태를 표시한다.

기능의 목적·입력·처리·출력은 기능명세에서 관리한다. 이 계획에는 수행할 작업과 확인할 결과를 기록한다.

5사용할 기술

공통 저장소와 기본 환경은 개발환경 및 코드 저장 위치에서 확인한다. 아래는 이 과제의 구성과 선택 상태이며, 해당 기능의 라이브러리·재사용 범위·실행 가능 여부는 착수 전에 확인한다.

구성 요소 선택 또는 후보 용도와 이유 근거·선택 상태
화면 구성 Dashboard / Map / Alarm / History / Command 장비 상태와 명령 결과 표시 기존 과제계획·R-05; 상세 화면 설계 미정
데이터 접점 DataProvider / Mock 공급자 실제 Core 없이 화면 시험, 이후 공급자 교체 기존 과제계획·R-05; 상세 계약 D-11 미정
GUI 프레임워크·언어·버전 미정 화면과 데이터 갱신 구현 공통 환경 확인됨; 기존 GUI 코드의 재사용 범위를 착수 전 확인 후 선택; 실습의 Vue·Vite를 자동 채택하지 않음

6 GUI-04 명령 입력과 요청별 상태·결과 표시를 구성한다. 대상·요청 ID·발행·동작 결과를 구분하여 표시한다.

7완료 기준

과제 전체 완료 체크

  • 원문에서 요구한 화면을 Mock AMR로 실행할 수 있다.
  • DataProvider 인터페이스와 Mock 공급자를 제공한다.
  • Map·상태·알람·이력·명령의 실제 화면 결과를 확인한다.
  • Mock과 실제 공급자 계약의 연결 방법을 기록한다.
  • 미정 디자인·정책과 실제 Core 연계 시험의 남은 범위를 표시한다.

위 체크는 실제 결과를 확인한 뒤 표시한다. 계획 초안 작성 완료와 과제 개발 완료를 구분한다.

다음 표는 예상 확인 결과이다. 현재 모든 항목의 실제 결과와 판정은 미검증이다.

GUI-02 서로 다른 장비 위치 변경과 Marker 선택 Map 위치와 선택 장비 ID·좌표·속도·State가 일치한다.
GUI-03 알람 발생·해제 및 기간·장비·유형 조회 현재 알람과 이력이 구분되고 조건별 결과·빈 결과·오류가 표시된다.
GUI-04 성공·거부·Timeout·역순 응답 Mock 원래 요청의 결과가 표시되고 발행 성공과 동작 완료가 구분된다.

실행 후에는 사용 설정·계약 버전, 입력, 절차, 예상 결과, 실제 결과, 판정 및 Log·화면·DB 등 근거를 검증 결과에 작성한다. 미정 정책에 의존하는 시험은 해당 결정 항목과 적용 값을 함께 기록한다.
