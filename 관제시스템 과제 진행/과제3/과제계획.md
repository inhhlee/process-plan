이 계획은 프로젝트의 과제3을 완료하기 위한 목표·작업 순서·산출물·확인 기준을 정리한다. 계획과 예상 결과를 작성한 상태이며 이 과제의 실제 구현·시험 결과는 이 문서에서 아직 확인하지 않았다. 기존 코드의 재사용 범위는 착수 전에 대조한다. 아래 작업 순서와 시험 항목은 요구사항·공통 규칙·데이터·기능명세를 기준으로 제안한 초기 계획이다.

## 2. 배경과 목적

공통 명세를 기반으로 Dashboard·Map·Alarm·History·Command 화면을 구성하고, Mock AMR로 독립 실행 가능한 GUI와 DataProvider 인터페이스를 제공한다.

## 3. 용어 설명

| 용어 | 쉬운 설명 |
| --- | --- |
| GUI | 사용자가 상태를 확인하고 명령을 입력하는 화면이다. |
| Mock | 실제 AMR·Core 대신 정해진 시험 데이터를 제공하는 대체 구현이다. |
| DataProvider | 화면에 데이터를 주고 명령 요청을 받는 공통 접점이다. 상세 계약은 D-11에서 정한다. |
| Map / Marker | 장비 위치를 보여 주는 지도 영역과 장비를 나타내는 표시다. |
| History | 과거 이벤트를 조회하는 정보다. 현재 상태나 현재 알람과 구분한다. |

### 제외·연계 범위

다음은 다른 과제의 담당 범위를 구분한 것이며 프로젝트 전체에서 제외한다는 뜻이 아니다.

| 항목 | 이유·담당 과제 |
| --- | --- |
| AMR·통신·Core의 업무 기능 구현 | 과제1·과제2·과제4 |
| 실제 Core를 포함한 전체 연결 검증 | 과제5; 이 과제의 Mock 검증과 구분 |

### 예정 산출물

| 산출물 | 위치 | 현재 상태 |
| --- | --- | --- |
| Mock AMR로 실행 가능한 GUI | `C:\practice` 내 대상 프로젝트 미정 — 착수 전 재사용 범위 확인 | 이 과제 적용 범위 미확인 — 기존 코드를 대조한 후 갱신 |
| DataProvider 인터페이스와 Mock 공급자 | 이 과제 `산출물/` 및 코드 저장소 내 위치 미정 — 작성 전 지정 | 미작성 — 착수·작성 시 실제 파일 연결 |
| Core 공급자 연결 계약 및 화면별 데이터 명세 | 담당 공통 명세 연결 및 이 과제 `산출물/` — 상세 파일명은 작성 전 지정 | 미작성 — 착수·작성 시 실제 파일 연결 |
| Mock 실행 안내와 화면별 검증 결과 | 이 과제 `산출물/` — 실행별 파일 생성 예정 | 미작성 — 착수·작성 시 실제 파일 연결 |

문서와 시험 근거는 이 과제의 `산출물/` 폴더에 관리할 계획이다. 아직 생성하지 않은 프로그램·시험 파일을 완료 결과물로 기록하지 않는다.

## 5. 사용할 기술

공통 저장소와 기본 환경은 [개발환경 및 코드 저장 위치](../개발환경%20및%20코드%20저장%20위치.md)에서 확인한다. 아래는 이 과제의 구성과 선택 상태이며, 해당 기능의 라이브러리·재사용 범위·실행 가능 여부는 착수 전에 확인한다.

| 구성 요소 | 선택 또는 후보 | 용도와 이유 | 근거·선택 상태 |
| --- | --- | --- | --- |
| 화면 구성 | Dashboard / Map / Alarm / History / Command | 장비 상태와 명령 결과 표시 | 기존 과제계획·R-05; 상세 화면 설계 미정 |
| 데이터 접점 | DataProvider / Mock 공급자 | 실제 Core 없이 화면 시험, 이후 공급자 교체 | 기존 과제계획·R-05; 상세 계약 D-11 미정 |
| GUI 프레임워크·언어·버전 | 미정 | 화면과 데이터 갱신 구현 | 공통 환경 확인됨; 기존 GUI 코드의 재사용 범위를 착수 전 확인 후 선택; 실습의 Vue·Vite를 자동 채택하지 않음 |

## 6. 개발 로드맵

### 선행 조건과 단계 흐름

- 선행 조건과 연계: DataProvider의 데이터 의미와 요청·결과 계약을 Core와 공유한다. Mock 공급자로 먼저 개별 시험하고 실제 Core 공급자 연계는 준비 상태에 맞춰 과제5에서 검증한다.

> 단계 흐름: 공급자 계약 → Mock 구성 → 요약·지도 → 알람·이력·명령 화면 → 화면 시험·정리

### 전체 작업 순서

이 계획의 개발 상태는 미착수로 유지하며 작업별 예정 기한은 미정이다. 기존 코드의 해당 과제 적용 범위를 확인한 뒤 실제 상태를 갱신한다. 필요한 설계 결정부터 정리하고 결정 내용을 적용한 버전으로 시험한다.

| 순서 | 관련 항목 | 수행할 작업 | 완료 확인 조건 |
| --- | --- | --- | --- |
| 1 | GUI-05 | D-11의 조회·변경 통지·명령 요청과 반환형을 정리한다. | Mock·Core 공급자가 공유할 계약과 오류·빈 결과·Mock 구분이 정의된다. |
| 2 | GUI-05 | 정상·변경·알람·명령 결과·오류를 재현하는 Mock 공급자를 작성한다. | 실제 AMR·Core 없이 화면 시험 자료를 제공한다. |
| 3 | GUI-01 | Dashboard의 요약·목록과 운행·통신 상태 표시를 구성한다. | Mock 자료와 요약·상세 표시가 일치한다. |
| 4 | GUI-02 | D-02에 따른 Map·Marker·선택 장비 정보를 구성한다. | 장비별 위치 갱신과 선택 정보가 일치한다. |
| 5 | GUI-03 | 현재 알람과 조건별 History 조회 화면을 구성한다. | 기간·장비·유형 조건, 빈 결과·오류 표시를 확인한다. |
| 6 | GUI-04 | 명령 입력과 요청별 상태·결과 표시를 구성한다. | 대상·요청 ID·발행·동작 결과를 구분하여 표시한다. |
| 7 | GUI-01~05 | 공급자 교체 구조와 화면별 Mock 시험 결과를 정리한다. | DataProvider 계약, 실행 안내, 실제 화면 근거와 미연결 범위를 기록한다. |
