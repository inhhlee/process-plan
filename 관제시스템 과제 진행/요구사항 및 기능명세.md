프로젝트 명세를 역할별 문서로 분리했다. 이 파일은 문서의 위치와 관계를 안내한다. R·C·기능·D 번호를 따라 요구사항, 기준, 데이터, 동작 및 결정 항목을 연결하여 확인한다.

상세 내용은 담당 문서에서 관리하고 다른 문서에서는 번호와 링크로 연결한다. 정책을 결정하면 결정사항에 근거를 기록하고 해당 규칙·데이터·기능명세를 갱신한다.

## 2. 확인 순서

1. 요구사항정의에서 프로젝트 범위와 과제별 결과물을 확인한다.
2. 공통규칙과 공통데이터명세에서 관련 기능이 사용할 기준과 계약을 확인한다.
3. 기능명세의 과제별 바로가기에서 목적·입력·처리·출력·확인 방법을 읽는다.
4. 해당 기능에 연결된 D 번호로 미정 정책과 후속 작업을 확인한다.
5. 각 과제계획에서 실제 수행할 작업과 완료 조건을 확인한다.

이번 작업을 바로 시작할 때는 [과제1의 이번 작업 단위](과제1/과제계획.md#com01-work) → [Heartbeat 계약과 예제](공통데이터명세.md#heartbeat-contract) → [기본 코딩 규칙](기본%20코딩%20규칙.md) → [시험 절차](과제1/과제계획.md#com01-test) 순서로 읽는다.

## 4. 현재 상태

- 요구사항 7개, 공유 규칙 11개, 기능 25개 및 결정 항목 12개를 각각의 담당 문서에 연결했다.
- 과제 1~5의 계획 초안에는 작업 순서·산출물·시험 계획·완료 기준을 작성했다.
- 문서 작성 상태는 완료이며 사용자 내용 검토와 설계 확정은 대기 상태이다.
- 2026-10-05에 사용자가 알려준 `C:\practice`를 확인했다. 과제1은 기존 Heartbeat 송수신 등을 부분 구현한 진행 중 상태이며, 환경 점검에서 빌드·자동 테스트 301개·Broker 접속과 구독을 확인했다. 상세 근거는 [환경 검증결과](과제1/산출물/2026-10-05_개발환경_검증결과.md)에 보존했다.
- 여섯 준비 항목의 결과는 [2026-10-05 일일업무](../일일업무/2026-10-05.md)에 연결한다. 환경 기준 문서는 같은 파일을 갱신하고, 시험 결과는 실행별로 기록한다. 실제 Heartbeat 송수신 재시험은 다음 작업이다.
- 원문 자료와 기존 초안의 역할은 요구사항정의의 자료별 역할에서 확인한다.

계획된 시험과 실제 수행 결과를 구분한다. 개발환경 점검 통과를 과제1의 전체 기능 또는 과제2~5의 통합 검증 통과로 처리하지 않는다.
