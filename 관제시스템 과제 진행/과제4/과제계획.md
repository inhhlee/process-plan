이 계획은 프로젝트의 과제4를 완료하기 위한 목표·작업 순서·산출물·확인 기준을 정리한다. 계획과 예상 결과를 작성한 상태이며 이 과제의 실제 구현·시험 결과는 이 문서에서 아직 확인하지 않았다. 기존 코드의 재사용 범위는 착수 전에 대조한다. 아래 작업 순서와 시험 항목은 요구사항·공통 규칙·데이터·기능명세를 기준으로 제안한 초기 계획이다.

## 2. 배경과 목적

GUI와 통신 사이의 핵심 서비스 계층을 라이브러리로 구성하여 장비·최신 상태·알람·명령·이력을 처리하고, 입력과 처리 결과를 개별 시험으로 확인한다.

## 3. 용어 설명

| 용어 | 쉬운 설명 |
| --- | --- |
| Core | 통신으로 들어온 정보를 처리하고 화면에 업무 결과를 제공하는 핵심 서비스다. |
| 라이브러리 | 다른 프로그램이 호출하여 사용할 수 있도록 묶은 기능이다. |
| SQLite | 이 프로젝트에서 업무 이력을 저장하고 조회할 데이터베이스다. |
| CommandId | 명령과 응답을 연결하는 식별자다. 생성 책임은 D-06에서 결정한다. |
| 현재 상태 / History | 지금의 최신 정보와 과거 이벤트 기록이다. 저장·조회 범위는 D-10에서 정한다. |

## 6. 개발 로드맵

### 선행 조건과 단계 흐름

- 선행 조건과 연계: 통신의 검증된 메시지와 GUI의 DataProvider 계약을 공유한다. 시험용 입력·조회 프로그램으로 Core를 개별 시험하며, SQLite 연계와 실제 DB 결과를 확인한다.

> 단계 흐름: 업무 계약 → 장비·최신 상태 → 알람·명령 → 이력 저장·조회 → 개별 시험·정리

### 전체 작업 순서

이 계획의 개발 상태는 미착수로 유지하며 작업별 예정 기한은 미정이다. 기존 코드의 해당 과제 적용 범위를 확인한 뒤 실제 상태를 갱신한다. 필요한 설계 결정부터 정리하고 결정 내용을 적용한 버전으로 시험한다.

| 순서 | 관련 항목 | 수행할 작업 | 완료 확인 조건 |
| --- | --- | --- | --- |
| 1 | CORE-01~05 | 장비 등록·최신 상태·알람·명령·History의 입력·결과 계약과 결정 항목을 검토한다. | 미등록·시각·ID 책임·ACK·저장·공급자 정책의 적용 범위가 정리된다. |
| 2 | CORE-01 | 장비 등록·조회와 중복·미등록 처리를 구성한다. | 장비 목록과 등록·거부 결과가 정책대로 반환된다. |
| 3 | CORE-02 | 최신 상태와 운행·통신 상태의 분리 관리를 구현한다. | 장비별 최신 데이터와 State 변화가 올바르게 연결된다. |
| 4 | CORE-03 | Alarm의 발생·해제·중복·재발생 관리를 구현한다. | 현재 알람과 변화 이력이 결정한 기준을 따른다. |
| 5 | CORE-04 | 명령 요청 기록, ID 연결, 상태·ACK·Timeout·예외 처리를 구현한다. | 다중 요청 결과와 잘못된 응답이 구분된다. |
| 6 | CORE-05 | D-10에 따른 SQLite 이벤트 저장과 조건 조회를 구현한다. | 상태·알람·명령 결과·운행 이력의 저장·조회 결과를 대조한다. |
| 7 | CORE-01~05 | 라이브러리 사용 방법과 개별 입력·처리·조회 시험을 정리한다. | 실제 결과·DB·오류 근거와 미해결 문제를 기록한다. |

## 7. 완료 기준

### 과제 전체 완료 체크

- [ ] 핵심 서비스 계층을 라이브러리 형태로 사용할 수 있다.
- [ ] 장비·상태·알람·명령·이력의 처리 결과를 개별 입력으로 확인한다.
- [ ] SQLite에 원문 범위의 업무 이력을 저장하고 조건 조회 결과를 확인한다.
- [ ] 요청 연결과 미등록·알람·응답·저장 예외에 적용한 정책을 기록한다.
- [ ] 실제 처리 결과·DB 결과·판정·사용 방법을 산출물에 연결한다.

위 체크는 실제 결과를 확인한 뒤 표시한다. 계획 초안 작성 완료와 과제 개발 완료를 구분한다.

다음 표는 예상 확인 결과이다. 현재 모든 항목의 실제 결과와 판정은 미검증이다.

실행 후에는 사용 설정·계약 버전, 입력, 절차, 예상 결과, 실제 결과, 판정 및 Log·화면·DB 등 근거를 검증 결과에 작성한다. 미정 정책에 의존하는 시험은 해당 결정 항목과 적용 값을 함께 기록한다.

### 이번 작업 시험

이번 작업은 미선정이며 아래 항목은 착수 전에 작성한다. 전체 시험 계획에서 선택한 범위를 구체화하며, 실제 결과는 실행별 검증결과에 기록한다.

미작성 — 이번 작업 선택 후 실행 환경·명령·순서·관찰 조건·기록 위치를 착수 전에 작성한다. 실제 시험 결과는 [검증결과 빈 양식](../../기준/양식/검증결과.md)을 사용해 이 과제의 `산출물/`에 남긴다.
