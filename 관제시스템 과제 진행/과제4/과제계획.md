이 계획은 과제4 전체 목표·작업·시험을 관리한다. 2026-10-28 두 AMR 통신 관측에 따른 제한된 Core 업무 처리를 구현·검증했으며 아래 최신 결과에 연결한다. 전체 업무/DB는 후속이고 과거 미착수 기록은 당시 이력으로 보존한다.

**2026-10-28 착수 — 두 AMR 독립 감시·Core 도메인 후속 처리**

- 사용자 요청으로 기존 AMR별 수신 큐를 재사용해 등록한 두 AMR의 Heartbeat를 독립 감시한다. 통신 관측 이벤트 → Core AMR 도메인 관리자 → 조회 상태/업무 경보 → GUI 경로를 추가한다. 기존 단일 AMR·Mock·F5 경로와 모든 미커밋 변경·증거를 보존하며 커밋·푸시·PR·병합은 하지 않는다.
- 사용자 선택 정책: 무응답/통신 단절에는 해당 AMR의 관제 미션을 보류하고 업무 경보를 표시한다. Heartbeat 복구로 생존/통신 관측과 경보는 복구하지만 미션은 자동 재개하지 않고 명시적 재개를 기다린다. 차량 이동 중단 명령·교통 노드 락·실제 안전 인터록은 이번 범위가 아니다. Telemetry 운행 상태와 관제 미션 보류는 구분한다.
- 기존 대상: Communication 세션/AMR별 큐/감시기, Core 공유 계약, Map 조립 호스트·GUI 공급자/폼. 생성 예정: Core AMR 도메인 관리자/입력·조회 모델·단위시험, 통신의 형식화 관측 이벤트와 다중 ID 감시, 두 AMR 호스트/변환 어댑터·설정·시험. Core는 MQTT·타이머·GUI 참조 없이 도메인 정책을 소유하고 통신은 미션을 모른다. 기존 F5 프로필은 유지하고 두 AMR 프로필을 추가한다.
- 완료조건/시험 입력·예상: A1 처리 지연에도 A2 큐 진행, 두 Heartbeat 정상→A1만 중단 시 A1무응답/미션 보류·경보1/A2정상, 복구 시 미션 보류 유지→명시 재개, 불량/미등록 ID 격리, Broker 단절 시 두 감시 중지/도메인 상태와 마지막 Telemetry 보존, 중복·이전 세션/늦은 입력 배제와 종료 정리. 자동 회귀·실제 MQTT·Windows Forms 두 장비/경보/선택/재개·기존 Mock/단일 F5를 대조한다.
- 착수 기준: HEAD4e44fa8·feature/46-grid-map-integration, 기존3263파일 SHA256 및 소스ZIP 백업 완료. 실행별 코드·입력·예상/실제·판정·실패/미검증은 `C:\amr-control-system-demo\evidence\COM-02\20261028-two-amr-domain-01\`에서 관리한다. 전체 Core/DB·교통/안전·장시간/대규모·과제 전체 완료로 확대하지 않는다.

**2026-10-28 후속 결과 — 제한된 Core 첫 업무 구현 로컬 완료**

- 신규 AmrDomainManager/AmrDomainModels가 등록한 두 ID의 최신 상태·관제 미션·통신 업무 경보·불변 조회를 관리한다. 통신 관측은 FleetCommunicationBridge가 Core 입력으로 변환한다. Core에는 MQTT·타이머·GUI 참조가 없고 I/O 없는 짧은 잠금으로 조회 일관성을 유지한다.
- [사용자 선택](../명세/검토%20및%20결정사항.md#two-amr-core-policy-20261028)대로 COMM_LOST/BROKER_LOST에서 해당 미션을 보류하고 경보를 만든다. 통신 복구는 활성 경보를 해제하되 명시 재개를 기다린다. 보류 중 도착은 완료 관측을 유지해 명시 재개 시 완료 처리한다. Telemetry 운행 State/물리 이동은 바꾸지 않는다. 이전 세션·중복/역순 관측·이전 미션 완료를 배제하며 마지막 Heartbeat/Telemetry를 보존한다.
- Core9·전체1141/1141, 실제 MQTT6단계·GUI 연계 통과. 불변 조회·동시 갱신·복구 후 보류·Broker 단절을 확인했다. [실행별 코드·입력/예상/실제·실패/한계·보존 감사](<C:/amr-control-system-demo/evidence/COM-02/20261028-two-amr-domain-01/README.md>) · [GUI 검증 구분](../과제3/과제계획.md#two-amr-domain-20261028).
- 메모리 내 두 대·관제 미션·통신 업무 경보의 제한 범위다. CORE-03 수신 Alarm 전체·정식 Command/ACK·DB·배차·교통 락·차량 Watchdog·자동 재접속·운영 전체 완료는 포함하지 않는다. 기존 Core 공유 계약·Mock·미커밋 변경·시험 근거를 유지했고 Git 게시 단계는 수행하지 않았다.

## 6. 개발 로드맵

### 선행 조건과 단계 흐름

- 선행 조건과 연계: 통신의 검증된 메시지와 GUI의 DataProvider 계약을 공유한다. 시험용 입력·조회 프로그램으로 Core를 개별 시험하며, SQLite 연계와 실제 DB 결과를 확인한다.

> 단계 흐름: 업무 계약 → 장비·최신 상태 → 알람·명령 → 이력 저장·조회 → 개별 시험·정리

### 전체 작업 순서

개발 상태는 제한된 Core 첫 업무 구현으로 진행 중이다. 두 AMR 최신 상태·통신 업무 경보·미션 보류/명시 재개만 완료했으며, 아래 표는 과제 전체 작업 순서다. 나머지 정책·업무/저장 구현·기한은 후속/미정으로 유지한다.

| 순서 | 관련 항목 | 수행할 작업 | 완료 확인 조건 |
| --- | --- | --- | --- |
| 1 | CORE-01~05 | 장비 등록·최신 상태·알람·명령·History의 입력·결과 계약과 결정 항목을 검토한다. | 미등록·시각·ID 책임·ACK·저장·공급자 정책의 적용 범위가 정리된다. |
| 2 | CORE-01 | 장비 등록·조회와 중복·미등록 처리를 구성한다. | 장비 목록과 등록·거부 결과가 정책대로 반환된다. |
| 3 | CORE-02 | 최신 상태와 운행·통신 상태의 분리 관리를 구현한다. | 장비별 최신 데이터와 State 변화가 올바르게 연결된다. |
| 4 | CORE-03 | Alarm의 발생·해제·중복·재발생 관리를 구현한다. | 현재 알람과 변화 이력이 결정한 기준을 따른다. |
| 5 | CORE-04 | 명령 요청 기록, ID 연결, 상태·ACK·Timeout·예외 처리를 구현한다. | 다중 요청 결과와 잘못된 응답이 구분된다. |
| 6 | CORE-05 | D-10에 따른 SQLite 이벤트 저장과 조건 조회를 구현한다. | 상태·알람·명령 결과·운행 이력의 저장·조회 결과를 대조한다. |
| 7 | CORE-01~05 | 라이브러리 사용 방법과 개별 입력·처리·조회 시험을 정리한다. | 실제 결과·DB·오류 근거와 미해결 문제를 기록한다. |

## 7. 완료 기준

### 과제 전체 완료 체크

- [ ] 핵심 서비스 계층을 라이브러리 형태로 사용할 수 있다.
- [ ] 장비·상태·알람·명령·이력의 처리 결과를 개별 입력으로 확인한다.
- [ ] SQLite에 원문 범위의 업무 이력을 저장하고 조건 조회 결과를 확인한다.
- [ ] 요청 연결과 미등록·알람·응답·저장 예외에 적용한 정책을 기록한다.
- [ ] 실제 처리 결과·DB 결과·판정·사용 방법을 산출물에 연결한다.

위 체크는 실제 결과를 확인한 뒤 표시한다. 계획 초안 작성 완료와 과제 개발 완료를 구분한다.
