## 3. 입력과 절차

- 제품 ConsoleRunner에서 단절 사유 코드·예외 유형·SocketError·UTC 감지 시각·Client ID를 기록하고 ShutdownRequested에도 원인을 표시했다. 최초 종료 원인 선택·정리 책임을 유지하며 자유 문구·예외 메시지는 기록하지 않는다.
- 실제 도구는 C1과 같은 `tests/manual/COM03-C/Verify-BrokerShutdown.ps1`에 작성했다. 기존 `tools/COM-03/` 생성 제안 대신 시험 도구 위치를 재사용한 것이며 제품 폴더 이동은 없다.
- 빌드·전체 자동시험 → 격리 Broker 접속·구독 → 해당 컨테이너 정상 종료 → 감지/정리/종료 확인 → 같은 컨테이너 재기동 → 새 콘솔 접속·12초 유지·PING·Ctrl+C → 시험 자원 정리를 수행했다. 실제 명령과 관찰 상한은 상세 검증결과에 연결한다.

## 5. 문제와 후속 조치

- NormalDisconnection은 MQTTnet이 보고한 프로토콜 사유 값이다. 사용자 취소가 없었으므로 애플리케이션은 ConnectionLost·종료 1로 처리했다. 사유 코드만으로 원격 원인을 확정하지 않는다.
- 감지/종료 시간은 docker stop 호출 직전 UTC부터 잰 이번 로컬 관찰값이다. Docker 명령·종료 관찰 지연을 포함하며 운영 SLA·응답 차단 감지 시간으로 확대하지 않는다.
- 최초 unit-01은 761건 통과·신규 시험 API 경고 1건이었다. 시험 파일 생성자만 지원 API로 교체해 unit-02에서 경고 0을 확인하고 이전 기록을 보존했다. 최종 단위시험 소스 69개는 일치, 실제 시험 당시 71개 중 차이는 이 시험 파일 1개뿐이며 제품·도구·바이너리 4개는 동일하다.
- 새 콘솔은 도구가 명시적으로 시작했다. 재기동 후 동적 Host port가 바뀌어 다시 조회했다. 자동 재접속이나 고정 주소 복구를 시험한 결과가 아니다.
