## 목적

최초 접속 실패·접속 대기 제한·사용자 취소를 구분한다. 연결되지 않은 상태를 성공으로 표시하거나 미처리 예외로 끝내지 않고, 실패·취소 후 새 실행에서는 정상 접속할 수 있게 한다.

착수 때 선행 A의 실제 파일명·설정·시험 경계와 대조한다. 이번 초안 조회 시 라이브러리·콘솔·시험 프로젝트는 존재하지만 연결 코드는 아직 없다.

- 빈 호스트·공백 호스트, 1~65535 범위를 벗어난 포트, 0 이하 접속 대기 제한을 연결 전에 거부하고 이유를 표시한다. 이름 해석·접속 가능 여부는 실제 접속 실패와 구분한다.
- Broker 접속 불가·접속 거부·설정한 접속 대기 제한 도달은 실패 상태·이유로 기록하고 Connected로 전환하지 않는다. 콘솔은 비정상 종료 코드로 끝내며 자원을 해제한다. 네트워크 전송 실패와 MQTT 접속 거부를 결과에서 구분한다.
- 접속 대기 중 Ctrl+C는 사용자의 취소로 기록하고 연결·자원 정리 후 종료 코드 0으로 끝낸다. 접속 대기 제한 때문에 발생한 취소와 사용자 취소를 혼용하지 않는다. 취소 직후 늦게 도착한 접속 결과도 성공 상태를 다시 만들지 않게 한다.
- 실패·취소 이후 올바른 설정으로 새 프로세스를 실행하면 정상 연결·종료할 수 있어야 한다. 자동 재시도·무한 대기·자동 재접속은 추가하지 않는다.
- 로그는 오류 유형·시각·판정에 필요한 원인만 남기고 자격증명을 포함하지 않는다. 기존 사용자 Broker·포트를 중단하거나 설정을 바꿔 실패 조건을 만들지 않는다.

## 제외 범위

연결 후 끊김·KeepAlive 감지(COM03-C), 인증 방식 신규 도입, 업무 Timeout·자동 재접속·재구독(COM-06), 메시지 송수신·AMR Heartbeat·GUI·Core·DB 및 운행 State·Alarm 판단.

## 완료조건

- [ ] 서비스가 없는 것으로 확인한 로컬 포트 접속은 원인을 기록하고 Connected 없이 비정상 종료한다.
- [ ] MQTT 접속 거부·전송 실패·대기 제한·사용자 취소의 결과와 종료 이유를 시험에서 구분한다.
- [ ] 잘못된 호스트·포트·접속 대기 제한 입력은 실제 연결 시도 전에 거부된다.
- [ ] 응답을 완료하지 않는 시험 대역에서 설정한 접속 대기 제한과 사용자 취소가 구분되고 무한 대기가 없다.
- [ ] 실패·취소 뒤 자원이 해제되며 늦은 접속 결과가 종료 상태를 Connected로 바꾸지 않는다.
- [ ] 실패·취소 시험 뒤 새 프로세스의 정상 접속·Ctrl+C 종료가 가능하고 필요한 정상 수명주기 회귀가 통과한다.
- [ ] 환경 문제·코드 실패·시험 대역·실제 네트워크 결과를 구분한 명령·설정·로그·판정을 Issue·PR에 연결한다.

## 시험 조건·입력·예상 결과

아래는 예정 시험이며 현재 결과는 미검증이다.

| 입력·조건 | 예상 결과 |
| --- | --- |
| 시험 직전 서비스가 없는 것으로 확인한 루프백 포트 | 최초 접속 실패·원인 기록, Connected 없음, 비정상 종료 코드 |
| 빈/공백 호스트, 포트 0 또는 65536, 접속 제한 0 또는 음수 | 입력 오류·이유 표시. 시험 대역 호출 횟수 0으로 연결 시도 없음 확인 |
| MQTT 접속을 거부하는 시험 대역 | 전송 실패와 구분되는 접속 거부 결과, 자원 정리, 비정상 종료 |
| 접속을 완료하지 않는 제어 가능한 시험 대역 | 설정한 제한 이후 대기 제한으로 실패 처리·자원 해제. 허용 오차를 실행 전에 기록 |
| 제한에 도달하기 전 접속 대기 중 사용자 취소 | 사용자 취소로 기록, Connected 없음, 자원 정리·종료 코드 0 |
| 취소·실패 처리 후 늦은 접속 완료 통지 | 종료 결과 유지, Connected 재전환·자원 잔류 없음 |
| 위 시험 뒤 정상 Broker 주소로 새 실행 | 선행 실패·취소 결과와 섞이지 않고 정상 연결·Ctrl+C 종료 |

대기 제한·취소 경계는 제어 가능한 시험 대역으로 검증한다. 실제 거절된 TCP 접속과 정상 MQTT 연결도 확인하며, 사용하지 않는 포트의 즉시 거절을 접속 대기 제한 시험으로 집계하지 않는다. 정상 Broker는 선행 A의 프로젝트 전용 설정을 사용한다. 단위 시험만으로 실제 MQTT 전체 통과를 주장하지 않는다.
