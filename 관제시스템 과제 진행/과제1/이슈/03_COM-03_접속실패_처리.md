### 1인 개발 학습·확인 순서

관련 개념을 질문하고 사용자 답변을 확인한 뒤 다음 단계로 진행한다. 이해가 부족한 부분은 설명한 뒤 다시 확인한다. 학습 답변은 구현·시험 완료 근거로 사용하지 않는다. 접속 대기 중 사용자가 Ctrl+C를 누른 결과는 사용자 취소이며, 설정한 제한에 도달해 기다림을 끝낸 접속 실패와 원인을 구분한다.

외부 선행은 #4의 정상 접속·종료와 시험 경계가 기준 브랜치에 반영되는 것이다. B1 → B2 → B3는 **같은 #5 브랜치·PR 안에서 앞 단계의 구현·결과를 확인하는 순서**이며 단계마다 병합을 요구하지 않는다. 확정 기한은 없고 실제 수행 결과를 보고 다음 단계로 넘어간다.

### COM03-B1 — 입력 오류·최초 접속 실패

먼저 익힐 내용은 입력 검사, 예외·오류 결과와 종료 코드다. 기본값과 유효한 입력을 유지하면서 잘못된 입력과 실제 접속 실패를 구분한다.

- [ ] #4에서 보완한 실제 접속 설정·연결 코드·콘솔·시험 경계를 확인한다. 빈/공백 호스트, 포트 0/65536, 접속 제한 0/음수의 여섯 입력은 연결 전에 거부하고 이유를 표시하며 실패로 종료한다. 호스트 이름 해석 실패는 입력 형식 검사와 구분한다.
- [ ] 기존 시험 프로젝트에서 잘못된 입력을 검사하고 시험 대역 연결 호출이 0인지 확인한다. README에 오류 입력·예상 결과를 기록한다.
- [ ] 시험 직전 서비스가 없는 것으로 확인한 루프백 포트에 실제 접속한다. 원인 기록·자원 정리·비정상 종료와 Connected 출력 없음을 확인한다. 기존 사용자 Broker·포트를 중단하거나 설정을 바꿔 실패 조건을 만들지 않는다.
- [ ] MQTT 접속 거부는 시험 대역으로 확인하고 네트워크 전송 실패와 다른 결과·이유로 기록한다. 인증 기능을 새로 도입하지 않는다.
- [ ] 실패 뒤 올바른 주소로 새 프로세스를 실행해 정상 접속·Ctrl+C 종료를 확인하고 관련 자동 시험·빌드 결과를 기록한다.

시간을 기다리는 접속 제한은 B2, 대기 중 사용자 취소는 B3에서 이어간다. 새 인증 방식·연결 후 끊김·업무 메시지는 이 단계에 포함하지 않는다.

<a id="com03-b2"></a>

### COM03-B2 — 접속 대기 제한·정리

선행은 같은 작업 안에서 B1의 입력 검사·실패 결과를 확인하는 것이다. 먼저 익힐 내용은 `CancellationToken`, 시간 제한과 제어 가능한 비동기 시험 대역이다.

- [ ] #4의 접속 제한 설정을 확인하고 연결 코드에서 실제 적용·제한 도달 원인·자원 정리를 보완한다. 실행 인자로 지정한 실제 제한값을 출력하며 기본 개발 제안값은 3초다.
- [ ] 기존 시험 경계에 접속을 완료하지 않는 대역을 두고 제한 도달을 재현한다. 제어할 수 있는 대기·취소 신호를 사용해 시험을 긴 실제 대기로 만들지 않는다.
- [ ] 허용 오차·측정 범위를 시험 전에 기록한다. 다른 유효한 제한값도 적용해 실제 적용값·측정값과 사전 기준이 대응하는지 확인하고 README에 제한 인자·실패 결과를 남긴다.
- [ ] 제한 도달은 접속 실패 이유로 기록하고 Connected 없이 대기 종료·자원 정리·비정상 종료한다. 제한 후 늦은 완료가 종료 상태를 성공으로 되돌리거나 연결·자원을 남기지 않는지 확인한다.
- [ ] 완료하지 않는 대역 시험과 관련 정상/실패 회귀 결과를 기록한다. 사용하지 않는 포트의 즉시 거절을 접속 대기 제한 통과로 집계하지 않는다.

사용자 취소와의 상세 구분은 B3에서 확인한다. KeepAlive·연결 후 무응답·업무 Timeout·자동 재시도는 이 단계에 포함하지 않는다.

<a id="com03-b3"></a>

### COM03-B3 — 사용자 취소·늦은 완료·새 실행

선행은 같은 작업 안에서 B2의 제한 도달·정리 결과를 확인하는 것이다. 먼저 익힐 내용은 사용자 취소와 시간 제한의 원인 구분, 늦은 비동기 결과다.

- [ ] 기존 콘솔의 종료 요청을 접속 대기에도 전달하고 연결 코드의 정리·결과를 보완한다. 완료되지 않는 접속 대역을 시작한 뒤 제한 이전에 콘솔 Ctrl+C 경로와 같은 취소 요청을 보낸다.
- [ ] 사용자 취소는 접속 성공·대기 제한 로그와 혼용하지 않고, Connected 없이 연결·자원을 정리한 뒤 종료 코드 0으로 끝낸다. 대기 제한 실패와 사용자 취소의 종료 원인·코드를 비교해 구분한다.
- [ ] 취소 뒤 늦은 접속 완료를 전달해 종료 상태가 유지되고 Connected 재전환·연결/자원 잔류가 없는지 확인한다.
- [ ] 실패·취소 뒤 실제 정상 Broker 주소로 새 프로세스를 실행해 정상 접속·Ctrl+C 종료를 확인하고 관련 자동 시험 결과를 기록한다.
- [ ] B1~B3의 실제 명령·환경·코드 버전·입력·적용 제한·허용 오차·예상·실제·판정·종료 코드·로그를 생성 예정 `evidence/COM-03/<새 실행ID>/`에 남겨 #5의 원래 완료조건 전체에 연결한다. 비밀정보·기존 C:\practice의 통과 결과를 복사하지 않고 이전 실패·취소·미검증 기록을 보존한다.

연결 후 단절·중복 알림·Ctrl+C와 단절 경합은 COM03-C에서 검증한다. 무한 재시도·자동 재접속·업무 기능은 이 단계에 포함하지 않는다. 정상/실패·대기 제한·취소의 유효한 근거를 확인한 뒤 다음 전체 작업은 [Issue 목록](README.md#solo-issues)을 따른다.

## 목적

최초 접속 실패·접속 대기 제한·사용자 취소를 구분한다. 연결되지 않은 상태를 성공으로 표시하거나 미처리 예외로 끝내지 않고, 실패·취소 후 새 실행에서는 정상 접속할 수 있게 한다.

## 완료조건

- [ ] 서비스가 없는 것으로 확인한 로컬 포트 접속은 원인을 기록하고 Connected 없이 비정상 종료한다.
- [ ] MQTT 접속 거부·전송 실패·대기 제한·사용자 취소의 결과와 종료 이유를 시험에서 구분한다.
- [ ] 잘못된 호스트·포트·접속 대기 제한 입력은 실제 연결 시도 전에 거부된다.
- [ ] 응답을 완료하지 않는 시험 대역에서 설정한 접속 대기 제한과 사용자 취소가 구분되고 무한 대기가 없다.
- [ ] 실패·취소 뒤 자원이 해제되며 늦은 접속 결과가 종료 상태를 Connected로 바꾸지 않는다.
- [ ] 실패·취소 시험 뒤 새 프로세스의 정상 접속·Ctrl+C 종료가 가능하고 필요한 정상 수명주기 회귀가 통과한다.
- [ ] 환경 문제·코드 실패·시험 대역·실제 네트워크 결과를 구분한 명령·설정·로그·판정을 Issue·PR에 연결한다.

| 시험 직전 서비스가 없는 것으로 확인한 루프백 포트 | 최초 접속 실패·원인 기록, Connected 없음, 비정상 종료 코드 |
| 빈/공백 호스트, 포트 0 또는 65536, 접속 제한 0 또는 음수 | 입력 오류·이유 표시. 시험 대역 호출 횟수 0으로 연결 시도 없음 확인 |
| MQTT 접속을 거부하는 시험 대역 | 전송 실패와 구분되는 접속 거부 결과, 자원 정리, 비정상 종료 |
| 접속을 완료하지 않는 제어 가능한 시험 대역 | 설정한 제한 이후 대기 제한으로 실패 처리·자원 해제. 허용 오차를 실행 전에 기록 |
| 제한에 도달하기 전 접속 대기 중 사용자 취소 | 사용자 취소로 기록, Connected 없음, 자원 정리·종료 코드 0 |
| 취소·실패 처리 후 늦은 접속 완료 통지 | 종료 결과 유지, Connected 재전환·자원 잔류 없음 |
| 위 시험 뒤 정상 Broker 주소로 새 실행 | 선행 실패·취소 결과와 섞이지 않고 정상 연결·Ctrl+C 종료 |

대기 제한·취소 경계는 제어 가능한 시험 대역으로 검증한다. 실제 거절된 TCP 접속과 정상 MQTT 연결도 확인하며, 사용하지 않는 포트의 즉시 거절을 접속 대기 제한 시험으로 집계하지 않는다. 정상 Broker는 선행 A의 프로젝트 전용 설정을 사용한다. 단위 시험만으로 실제 MQTT 전체 통과를 주장하지 않는다.
