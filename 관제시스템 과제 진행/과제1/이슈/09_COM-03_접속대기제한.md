## 목적

접속 응답이 끝나지 않는 경우 설정한 시간 후 기다림을 끝내고 정리한다. 즉시 접속 거절과 시간을 기다린 뒤의 대기 제한을 구분한다.

## 근거와 선행 조건

- 선행: [COM03-B1](08_COM-03_입력오류와_접속실패.md)의 변경·결과 반영. 게시 시 실제 Issue URL을 연결한다.
- 먼저 익힐 내용: CancellationToken·시간 제한과 제어 가능한 비동기 시험 대역. 확정 기한은 없고 한 작업을 확인한 뒤 다음 작업을 진행한다.

## 이번에 할 일

- A2의 접속 제한 설정을 확인하고 연결 코드에서 실제 적용·제한 도달 원인·자원 정리를 보완한다.
- 기존 시험 경계에 접속을 완료하지 않는 대역을 두어 제한 도달과 늦은 완료 상태를 시험한다.
- README에 제한 인자·실패 결과를 기록한다. 실제 동작·측정값과 시험 허용 오차를 남긴다.

## 진행 순서

1. 제한을 실행 인자로 바꾸고 실제 적용값을 출력한다. 기본 개발 제안값은 3초다.
2. 완료하지 않는 대역으로 제한 도달을 재현한다. 제어할 수 있는 대기·취소 신호를 사용하고 시험을 긴 실제 대기로 만들지 않는다.
3. 대기 제한 후 실패·정리·종료를 확인한다. 늦은 접속 결과는 성공 상태를 되돌리지 않도록 처리한다.

## 완료조건

- [ ] 접속 대기 제한 도달을 이유로 기록하고 Connected 없이 자원 정리·비정상 종료한다.
- [ ] 입력한 제한값이 적용되고 허용 오차·측정 범위를 시험 전에 기록한다.
- [ ] 제한 이후 늦은 결과가 종료 상태를 성공으로 바꾸거나 자원을 남기지 않는다.
- [ ] 완료하지 않는 대역 시험과 관련 정상/실패 회귀가 성공한다. 즉시 포트 거절을 시간 제한 통과로 집계하지 않는다.

## 시험 방법과 예상 결과

예정 시험이며 현재 결과는 미검증이다.

| 입력·절차 | 예상 결과 |
| --- | --- |
| 접속을 완료하지 않는 대역 | 제한 도달, 대기 종료·정리·실패 종료 |
| 다른 유효한 접속 제한값 | 실제 적용값 및 사전 허용 범위와 결과 대응 |
| 제한 이후 늦은 접속 완료 | Connected 재전환·자원 잔류 없음 |

## 제외 범위

사용자가 직접 Ctrl+C로 취소하는 상세 구분은 B3이다. KeepAlive·연결 후 무응답·업무 Timeout·자동 재시도를 추가하지 않는다.
