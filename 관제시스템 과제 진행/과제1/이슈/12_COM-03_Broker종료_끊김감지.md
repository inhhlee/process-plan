## 목적

연결 중인 시험 Broker를 종료하면 콘솔이 연결 상실을 표시하고 정리·종료하도록 한다. Broker가 다시 켜지는 것과 새 프로세스의 명시적 접속을 구분한다.

## 근거와 선행 조건

- 관련 기준: 기능명세 v0.7 COM-03, 요구사항정의 v0.5 R-04, 공통규칙 v0.4 C-04·C-09·C-10,결정사항 v0.5 D-08·D-09. 개인 실습 분할 제안이며 기존 Issue #6의 최종 완료조건을 유지한다.
- 선행: [COM03-C1](11_COM-03_KeepAlive_연결유지.md)의 변경·결과 반영. 게시 시 실제 Issue URL을 연결한다.
- 작업 구분: 기본. 먼저 익힐 내용은 MQTT 단절 통지·상태 변화·격리 시험용 Broker이다. 확정 기한은 없고 앞선 결과를 확인한 뒤 한 작업씩 진행한다.

## 이번에 할 일

- 기존 연결 코드·콘솔에서 단절 상태·원인·시각을 전달하고 예상치 못한 단절은 정리 후 비정상 종료한다.
- 생성 예정 `tools/COM-03/`에 기존 Docker 설정을 참고한 별도 프로젝트명·루프백 임시 포트·분리된 데이터/로그의 시험 Broker 설정을 둔다.
- 기본 단절 동작 자동 시험과 실제 Broker 종료·새 실행 접속 결과를 기록한다.

## 진행 순서

1. 기존 사용자 Broker·A1의 Broker를 중단하지 않도록 별도 시험용 인스턴스와 관리 범위를 확인한다.
2. 실제 라이브러리·설정을 근거로 관찰 상한을 정한 뒤 연결한 시험 Broker만 정상 종료한다.
3. 단절 출력·정리·종료 코드를 확인한다. 시험 Broker 재기동 후 새 콘솔을 실행해 새 ID의 접속을 확인한다.

## 완료조건

- [ ] 격리 Broker의 이름·포트·설정·관리 자원이 기존 실행과 분리돼 있다.
- [ ] 실제 Broker 정상 종료 후 정한 관찰 범위 내에 연결 상실·원인·시각이 보이고 정리 후 비정상 종료한다.
- [ ] 명시적 Ctrl+C 정상 종료와 예상치 못한 단절을 구분하고 같은 단절을 반복 상태 변화로 출력하지 않는다.
- [ ] Broker 재기동 뒤 새 실행 접속을 확인한다. 자동 복구로 표시하지 않으며 기본 자동 시험·관련 회귀가 성공한다.
