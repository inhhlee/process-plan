## 작업 순서

1. 연결 후 취소 요청, 종료를 기다리는 흐름, xUnit 시험 대역을 이해한다.
2. 연결 전·연결 후·명시적 종료 상태를 구분하고, 승인된 연결을 Ctrl+C까지 유지한다.
3. 종료 요청을 받으면 라이브러리의 연결 해제를 기다린 뒤 자원을 정리한다. 미처리 예외 없이 종료 코드 0으로 끝낸다.
4. 실제 Broker 접속 → Ctrl+C 종료 → 새 프로세스 재실행을 수행한다. 이전 세션·새 Client ID를 콘솔/Broker 로그로 구분한다.
5. 정상 접속·명시적 종료·반복 정리를 시험 대역으로 검증한다. 승인 전 성공 표시가 없고 종료 후 상태·정리 결과가 맞는지 확인한다.
6. 빌드·자동 시험·실제 Broker 결과를 분리하고, A1~A3 근거가 최종 코드에도 유효한지 대조한다. 영향받는 항목만 회귀한다.

## 제외 범위

접속 대기 중 취소·늦은 접속 결과·상세 실패 분류는 [#5](https://github.com/inhhlee/amr-control-system-demo/issues/5), KeepAlive 진단·Broker 비정상 단절·무응답·종료 경합은 [#6](https://github.com/inhhlee/amr-control-system-demo/issues/6)에서 검증한다. 이번의 연결 유지는 정상 콘솔 수명주기이며 #6의 프로토콜 유지 검증을 대체하지 않는다. 메시지 구독·발행·자동 재접속·GUI·Core·DB는 포함하지 않는다.
