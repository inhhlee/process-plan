## 목적

Broker 접속을 기다리는 중 Ctrl+C를 누르면 사용자 취소로 종료한다. 시간 제한으로 끝난 실패와 구분하고 취소 뒤 늦은 결과도 정리한다.

## 근거와 선행 조건

- 관련 기준: 기능명세 v0.7 COM-03, 요구사항정의 v0.5 R-04, 공통규칙 v0.4 C-04·C-10. 개인 실습 분할 제안이며 기존 Issue #5의 최종 완료조건을 유지한다.
- 선행: [COM03-B2](09_COM-03_접속대기제한.md)의 변경·결과 반영. 게시 시 실제 Issue URL을 연결한다.
- 먼저 익힐 내용: 사용자 취소와 시간 제한의 원인 구분·늦은 비동기 결과. 확정 기한은 없고 한 작업을 확인한 뒤 다음 작업을 진행한다.

## 이번에 할 일

- 기존 콘솔의 종료 요청을 접속 대기에도 전달하고 연결 코드의 정리·결과를 보완한다.
- 기존 시험 프로젝트에 제한 이전 사용자 취소·늦은 완료·이후 정상 실행 동작 시험을 추가한다.
- B1~B3의 결과와 기존 Issue #5 완료조건을 연결한다.

## 진행 순서

1. 끝나지 않는 접속 대역을 시작한 뒤 제한에 도달하기 전에 취소 신호를 보낸다. 콘솔의 Ctrl+C 경로와 같은 취소 요청을 사용한다.
2. 사용자 취소는 성공 접속·대기 제한 로그와 혼용하지 않고 정리 후 종료 코드 0으로 끝낸다.
3. 취소 뒤 늦은 완료를 전달해 상태 유지·정리를 확인한다. 실제 정상 Broker로 새 프로세스를 실행해 회복 가능성을 확인한다.

## 완료조건

- [ ] 접속 중 사용자 취소는 사용자 취소로 기록하고 Connected 없이 자원 정리·종료 코드 0이다.
- [ ] 접속 제한에 의한 실패와 사용자 취소의 종료 원인·코드를 구분한다.
- [ ] 취소 뒤 늦은 완료가 Connected를 만들거나 연결·자원을 남기지 않는다.
- [ ] 실패·취소 뒤 새 실행의 정상 연결·Ctrl+C 종료와 관련 자동 시험이 성공한다. B1~B3 근거를 기존 Issue #5에 연결한다.

## 시험 방법과 예상 결과

예정 시험이며 현재 결과는 미검증이다.

| 입력·절차 | 예상 결과 |
| --- | --- |
| 접속 대기 중 제한 이전 취소 | 사용자 취소·정리·정상 종료 0 |
| 대기 제한 결과와 취소 결과 비교 | 실패/취소의 원인·종료 코드 구분 |
| 취소 후 늦은 완료, 이어서 실제 정상 주소로 새 실행 | 종료 상태 유지·자원 정리·새 실행 정상 연결 |

## 제외 범위

연결 후 Broker 단절·중복 알림·Ctrl+C와 단절 경합은 C 작업이다. 무한 재시도·자동 재접속·업무 기능은 추가하지 않는다.
