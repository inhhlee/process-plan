## 목적

실제 Broker를 통한 명령·ACK 왕복에서 결과와 식별자가 보존되는지 Core 대역으로 확인한다.

- 근거: 기능명세 v0.7 COM-05, 요구사항정의 v0.5 R-04, 공통규칙 v0.4, 공통데이터명세 v0.4 과제1 개발 계약, 검토 및 결정사항 v0.5. 작업 분할·실습 순서는 신입 1인 개발을 위한 제안이다.

- 먼저 익힐 내용: ACK는 특정 요청에 대한 응답이다. 도착 순서 대신 AMR ID와 CommandId로 원래 요청을 찾는다.

## 작업 범위와 대상

- 개발 위치: `C:\amr-control-system-demo`. 대상: Command/·ACK 전달부, 콘솔 Core 대역·최소 AMR 시험 도구(생성 예정), 자동 시험.
- 라이브러리·콘솔·시험 프로젝트는 준비돼 있다. 제품 소스는 현재 없으므로 위 모듈은 새로 만들거나 선행 작업에서 생성한 파일을 보완할 예정이며, 착수 시 실제 구조·기존 변경을 대조한다.
- 요청 ID·대상을 보관하는 최소 Core 시험 대역과 ACK를 돌려주는 최소 AMR 대역을 준비한다. 운영 Core·시뮬레이터를 대신 구현하지 않는다.
- 유효한 ACK의 cmdId·대상·result·ts·선택 reason을 그대로 전달한다. 여러 AMR의 응답을 역순으로 보내도 정확한 원래 요청에 연결한다.
- 시험용 SUCCESS/FAILURE 응답과 실제 장비 동작을 구분한다. 불량 ACK는 COM-04에서 거부한다. 미요청·중복·늦은 ACK의 업무 처리·ACK Timeout은 D-07/CORE-04 후속 결정으로 표시한다.

## 완료조건

- [ ] MOVE·STOP·RESET의 요청부터 ACK 전달까지 같은 ID로 추적할 수 있다.

- [ ] 불량 ACK는 전달되지 않으며 잘못된 대상의 응답을 다른 AMR의 요청과 매칭하지 않는다.

## 시험 방법과 예상 결과

아래는 예정 확인이며 현재 실행 결과가 아니다.

| 입력·조건 | 예상 결과 |
| --- | --- |
| 두 AMR의 여러 요청에 ACK를 역순 반환 | 원래 AMR+cmdId 조합에만 매칭 |
| SUCCESS·FAILURE, reason 생략/포함 | 수신 값 보존, 발행 성공과 ACK 결과 구분 |
