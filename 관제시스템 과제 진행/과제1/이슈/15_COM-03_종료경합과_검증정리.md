## 목적

같은 단절을 여러 번 알리거나 종료 요청과 단절이 근접해도 정리·종료가 가능하도록 확인한다. 앞선 단계의 유효한 근거를 모아 기존 #4~#6의 완료조건을 판단한다.

## 근거와 선행 조건

- 관련 기준: 기능명세 v0.7 COM-03, 요구사항정의 v0.5 R-04, 공통규칙 v0.4 C-04·C-09·C-10,결정사항 v0.5 D-08·D-09. 개인 실습 분할 제안이며 기존 Issue #6의 최종 완료조건을 유지한다.
- 선행: [COM03-C3b](14_COM-03_무응답_감지측정.md)의 변경·결과 반영. 게시 시 실제 Issue URL을 연결한다.
- 작업 구분: 후속 검증. 먼저 익힐 내용은 시험 대역의 알림 순서 제어·중복 정리·회귀 범위이다. 확정 기한은 없고 앞선 결과를 확인한 뒤 한 작업씩 진행한다.

## 이번에 할 일

- 기존 연결 코드·시험 프로젝트에서 필요한 중복 통지·종료 처리만 보완한다.
- 같은 세션 중복 단절, Ctrl+C→단절, 단절→Ctrl+C, 종료 후 늦은 단절 알림을 제어된 대역으로 시험한다. B3의 늦은 접속 완료 시험은 변경 영향이 없으면 기존 근거를 활용한다.
- README·증거 목록에 A1~C3b 결과와 최종 코드에 대한 유효성·필요한 회귀를 연결한다.

## 진행 순서

1. 동시성 시험을 무작위 대기 대신 제어 가능한 알림 순서로 재현한다.
2. 실제로 결정한 종료 원인·상태·코드가 맞고 정리·종료가 완료되는지 확인한다.
3. 변경 영향이 있는 앞선 시험만 회귀한다. 기존 Issue #4·#5·#6의 원래 완료조건별로 유효한 근거와 미검증 범위를 정리한다.

## 완료조건

- [ ] 같은 세션의 중복 단절은 상태 변화·정리·종료를 중복 실패시키지 않는다.
- [ ] 두 종료 순서에서 결정된 이유·코드가 일치하고 예외·정리 실패·무한 대기가 없다.
- [ ] 종료 후 늦은 연결·단절 알림은 종료 결과를 되돌리거나 Connected를 만들지 않는다.
- [ ] 정상·실패·대기 제한·취소·KeepAlive·Broker 종료·무응답의 실제 근거와 관련 회귀를 최종 코드 버전에 연결한다.
- [ ] 기존 #4~#6의 미충족 항목을 표시한다. 모두 충족한 범위만 완료 판단하고 과제1 전체·다른 COM 기능·기존 C:\practice 상태를 자동 변경하지 않는다.

## 시험 방법과 예상 결과

예정 시험이며 현재 결과는 미검증이다.

| 입력·절차 | 예상 결과 |
| --- | --- |
| 같은 세션의 중복 단절 알림 | 한 번의 상태 변화, 중복 정리 실패 없음 |
| Ctrl+C→단절 및 단절→Ctrl+C 순서 | 선택한 종료 원인·코드 일치, 정리·종료 가능 |
| 종료 후 늦은 알림 및 필요한 회귀 | 종료 상태 유지, 영향 시험 통과·근거 목록 연결 |

## 제외 범위

새 제품 기능·부하 시험·모든 동시 실행 순서의 전수 시험·운영 정책 확정은 포함하지 않는다. 영향 없는 과거 시험을 문서 정리 때문에 반복하지 않는다.
