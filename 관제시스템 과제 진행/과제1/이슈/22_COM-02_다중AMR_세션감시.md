## 목적

장비별 감시를 독립적으로 수행하고 Broker 단절·종료 때 이전 감시를 정리한다.

## 근거와 선행 조건

- 근거: 기능명세 v0.7 COM-02, 요구사항정의 v0.5 R-04, 공통규칙 v0.4, 공통데이터명세 v0.4 과제1 개발 계약, 검토 및 결정사항 v0.5. 작업 분할·실습 순서는 신입 1인 개발을 위한 제안이다.
- 선행 작업: [COM02-A](21_COM-02_Heartbeat_중단과복구.md)의 해당 결과 반영. 추천 진행 순서는 Issue 목록을 따른다.
- 먼저 익힐 내용: 세션은 한 번의 Broker 연결부터 종료까지다. 과거 세션의 시각과 알림을 다음 연결에 섞지 않는다.

## 작업 범위와 대상

- 개발 위치: `C:\amr-control-system-demo`. 대상: 선행 Monitoring/·Mqtt/ 세션 경계와 자동 시험, README·증거.
- 라이브러리·콘솔·시험 프로젝트는 준비돼 있다. 제품 소스는 현재 없으므로 위 모듈은 새로 만들거나 선행 작업에서 생성한 파일을 보완할 예정이며, 착수 시 실제 구조·기존 변경을 대조한다.
- 한 AMR만 중단했을 때 그 대상만 Timeout되게 하고 정상 수신은 Core 큐가 막혀도 생존 시각을 갱신한다.
- Broker 단절 감지·종료 시 감시를 중단하고 명시적 새 연결에서는 첫 정상 Heartbeat부터 새로 시작한다.
- 이전 세션의 늦은 입력·알림과 종료 경합을 자동 시험으로 확인한다. 재연결된 세션의 자동 복구 연결은 COM06-B·C가 담당한다.

## 진행 순서

1. 선행 결과와 이번 기준을 읽고 정상 입력 하나·예상 출력부터 확인한다.
2. 위 작업 범위를 순서대로 구현하거나 정리한다. 처음부터 범용 프레임워크를 만들지 않는다.
3. 아래 사례로 결과를 확인하고 실행 방법·남은 범위를 기록한다. 한 작업이 너무 크면 실제 진행 결과에 따라 나머지 범위를 분리한다.

## 완료조건

- [ ] 정상 AMR과 중단 AMR의 결과가 분리된다.
- [ ] 느린 Core·가득 찬 큐가 정상 Heartbeat 수신 시각을 늦추지 않는다.
- [ ] Broker 단절·종료 후 이전 세션의 AMR Timeout을 계속 생성하지 않는다.
- [ ] 새 연결은 과거 대상·시각을 재사용하지 않는다.
- [ ] 실제 변경·확인 결과·미검증 범위를 README와 Issue·PR에 연결한다.

## 시험 방법과 예상 결과

아래는 예정 확인이며 현재 실행 결과가 아니다.

| 입력·조건 | 예상 결과 |
| --- | --- |
| 두 장비 중 하나만 Heartbeat 중단 | 해당 AMR만 Timeout, 다른 AMR 정상 |
| Core 대역 정지/큐 초과 상태에서 정상 Heartbeat 지속 | 수신 기준 감시는 정상 유지 |
| Broker 중단·Ctrl+C·명시적 새 연결, 이전 알림 지연 | 구 세션 정리·새 감시 시작 조건 유지 |

## 제외 범위

실제 Core/AMR 통합, 자동 재접속 자체.
