## 목적

콘솔에서 Broker에 한 번 접속해 승인 결과를 출력한 뒤 연결을 해제하고 종료한다. 한 번의 성공 흐름을 이해한 다음 계속 실행·Ctrl+C 처리를 추가한다.

## 근거와 선행 조건

- 선행: [COM03-A1](05_COM-03_Broker_기동확인.md)의 변경·결과가 기준 브랜치에 반영돼 있어야 한다. 게시 시 실제 Issue URL로 연결한다.
- 먼저 익힐 내용: MQTT 접속 승인, await, try/finally와 자원 정리. 이번 작업의 확정 기한은 없으며 실행 결과를 확인한 뒤 다음 작업으로 넘어간다.

## 이번에 할 일

- 기존 통신 라이브러리에 생성 예정 `Mqtt/`의 최소 접속 설정·연결·명시적 해제 코드를 작성한다. MQTTnet 5.2.0.1603을 유지한다.
- 기존 `src/Amr.Communication.Console/Program.cs`에서 접속 요청 → 결과 출력 → 연결 해제 → 종료 흐름을 작성한다.
- 호스트·포트·접속 제한을 실행 인자로 받고 적용 주소·고유 Client ID를 기록한다. 일반화된 통신 프레임워크를 만들지 않는다.

## 진행 순서

1. 기본 개발 설정은 로컬 1884, MQTT 5, Clean Start, 실행별 고유 Client ID, KeepAlive 5초·접속 제한 3초로 적용하고 실제 값을 출력한다.
2. 정상 접속 승인 뒤에만 `Connected`를 출력한다. 이번 콘솔은 연결 성공 직후 명시적으로 해제·정리하고 종료한다.
3. 실제 Broker 로그의 같은 Client ID와 콘솔 결과를 대조하고 재실행한다. 실패는 Connected로 숨기지 않는 최소 처리만 한다.

## 완료조건

- [ ] 실제 Broker 승인 후 Connected가 표시되고 적용 주소·설정·Client ID를 기록한다.
- [ ] 정상 실행은 연결 해제·자원 정리 후 종료 코드 0이며 새 실행은 다른 Client ID로 접속한다.
- [ ] 최소 실패 결과에서는 Connected를 출력하지 않는다. 상세 오류·취소 검증은 B 작업으로 넘긴다.
- [ ] 복원·빌드와 실제 접속 로그를 기록하고 재현할 콘솔 명령을 README에 작성한다.

예정 시험이며 현재 결과는 미검증이다.

| 입력·절차 | 예상 결과 |
| --- | --- |
