## 학습·작업 순서

### A2 — 한 번 접속·명시적 해제

1. MQTT 접속 승인, `await`, `try/finally`와 자원 정리의 의미를 질문·답변으로 확인한다.
2. 최소 접속·명시적 해제 코드를 기존 라이브러리에 작성하고 콘솔에서 호출한다.
3. 성공한 MQTT 승인 뒤에만 `Connected`를 표시한다. 최초 승인 실패를 성공으로 숨기지 않는 최소 처리와 자원 정리를 포함한다.
4. 실제 Broker에 접속한 뒤 명시적으로 해제·정리하고 종료 코드 0을 확인한다. 새 프로세스도 실행해 다른 Client ID와 같은 실행의 콘솔/Broker 로그를 대조한다.
5. 실제 코드 버전·미커밋 변경·인자·설정과 복원·빌드·실행 증거를 남긴다. 이 중간 결과를 확인한 뒤 같은 브랜치에서 A3로 진행한다.

### A3 — 연결 유지·Ctrl+C 정상 종료

1. 연결 후 취소 요청, 종료를 기다리는 흐름, xUnit 시험 대역을 질문·답변으로 확인한다.
2. A2의 코드·실행 근거·실제 인자·설정과 기존 변경을 대조한다. 연결 전·연결 후·명시적 종료 상태를 구분하고 승인된 연결을 Ctrl+C까지 유지한다.
3. 종료 요청을 받으면 연결 해제를 기다린 뒤 자원을 정리하고 미처리 예외 없이 종료 코드 0으로 끝낸다.
4. 실제 접속 → Ctrl+C 종료 → 새 프로세스 재실행을 확인한다. 이전 세션·새 Client ID를 콘솔/Broker 로그로 구분하고 자원 잔류를 확인한다.
5. 시험 대역으로 정상 접속·명시적 종료·반복 정리와 승인 전 성공 표시가 없음을 확인한다.
6. 복원·빌드·자동 시험·실제 Broker 결과를 구분하고 A1 및 A2 중간 근거의 최종 코드 유효성을 대조한다. 영향받는 항목만 회귀하고 총괄 #4의 원래 완료조건 전체에 증거를 연결한다.

A2의 즉시 해제는 검증할 중간 결과이며 최종 콘솔 동작은 A3의 연결 유지·Ctrl+C 종료다. 최종 사용자용 즉시 해제 모드를 별도로 추가할 필요는 없다. 중간 코드 버전과 증거를 보존하고 최종 코드에서 유지되는 접속·해제·정리 동작을 다시 대조한다.
