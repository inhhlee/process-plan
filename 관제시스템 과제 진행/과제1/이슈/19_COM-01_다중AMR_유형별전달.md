## 목적

검사한 Heartbeat·Telemetry·Alarm·ACK를 대상 AMR과 유형에 맞게 시험 수신자에 전달한다.

## 근거와 선행 조건

- 근거: 기능명세 v0.7 COM-01, 요구사항정의 v0.5 R-04, 공통규칙 v0.4, 공통데이터명세 v0.4 과제1 개발 계약, 검토 및 결정사항 v0.5. 작업 분할·실습 순서는 신입 1인 개발을 위한 제안이다.
- 선행 작업: [COM04-B](18_COM-04_메시지유형_확장검사.md)의 해당 결과 반영. 추천 진행 순서는 Issue 목록을 따른다.
- 먼저 익힐 내용: 장비 ID는 누구의 데이터인지, 메시지 유형은 어떤 데이터인지를 구분한다. 시험 장비 두 대는 설명용 수량이다.

## 작업 범위와 대상

- 개발 위치: `C:\amr-control-system-demo`. 대상: 선행 Mqtt/ 구독부·검사기 연결, 콘솔의 Core 대역, 최소 시험 JSON·README.
- 라이브러리·콘솔·시험 프로젝트는 준비돼 있다. 제품 소스는 현재 없으므로 위 모듈은 새로 만들거나 선행 작업에서 생성한 파일을 보완할 예정이며, 착수 시 실제 구조·기존 변경을 대조한다.
- 선행 구독 목록을 네 유형으로 확장하고 COM04-A·B 검사기를 연결한다.
- Core 대역에 AMR ID·유형·모델·수신 시각을 전달한다. GUI·실제 Core를 만들지 않는다.
- 준비한 Broker의 CLI와 작은 JSON 시험 자료로 장비 두 대의 입력을 재현한다. 이미 검토한 예제를 재사용하고 최소 추가 자료만 작성한다.

## 진행 순서

1. 선행 결과와 이번 기준을 읽고 정상 입력 하나·예상 출력부터 확인한다.
2. 위 작업 범위를 순서대로 구현하거나 정리한다. 처음부터 범용 프레임워크를 만들지 않는다.
3. 아래 사례로 결과를 확인하고 실행 방법·남은 범위를 기록한다. 한 작업이 너무 크면 실제 진행 결과에 따라 나머지 범위를 분리한다.
