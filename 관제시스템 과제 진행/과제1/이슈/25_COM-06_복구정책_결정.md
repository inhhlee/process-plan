## 작업 범위와 대상

- 개발 위치: `C:\amr-control-system-demo`. 대상: README의 개발 복구 정책·설정 설명 및 시험표(작성 예정); 원본 결정사항은 C:\process-plan에서 합의 결과 연결.
- 라이브러리·콘솔·시험 프로젝트는 준비돼 있다. 제품 소스는 현재 없으므로 위 모듈은 새로 만들거나 선행 작업에서 생성한 파일을 보완할 예정이며, 착수 시 실제 구조·기존 변경을 대조한다.
- 재시도 대상(최초 실패/연결 후 단절), 간격 방식·횟수·최대 대기, 중단 조건과 실패 표시를 선택한다. 기존 COM03-B의 최초 실패 종료와 무엇이 달라지는지 명시한다.
- 재구독 목록·완료 판단과 구독 실패 때 동작을 정한다. MQTT 연결됨과 송수신 준비 완료를 구분한다.
- 끊기기 전 발행된 미응답 명령과 끊긴 동안 새 요청의 처리(폐기/보류/재전송), 실패·결과 불명 표시 책임을 선택한다. 재전송을 택하면 중복 실행 방지·ID 보존·ACK 정책의 추가 범위를 정한다.

1. 선행 결과와 이번 기준을 읽고 정상 입력 하나·예상 출력부터 확인한다.

3. 아래 사례로 결과를 확인하고 실행 방법·남은 범위를 기록한다. 한 작업이 너무 크면 실제 진행 결과에 따라 나머지 범위를 분리한다.

### 검토할 선택지

- 입문 권고안(미승인): 유한 횟수의 일정 간격 재시도. Backoff보다 관찰·시험이 단순하다. 간격·횟수는 실제 시험 환경을 보고 결정한다.
- 명령 권고안(미승인): 통신 계층에서 자동 재전송하지 않고 단절 중 새 요청은 거부한다. 이미 발행한 미응답 요청은 실제 수행 여부를 알 수 없으므로 성공·미실행을 단정하지 않고 요청 측에 단절/결과 불명을 전달한다.
- 보류·재전송을 택하면 저장·중복 수행 방지·늦은 ACK 처리가 필요하므로 별도 작업 범위를 추가한다. 기능명세의 복구 요구를 없애지 않고 선택한 정책에 대한 검증으로 다룬다.

정책 선택은 이 작업을 수행할 때 사용자와 정한다. 이번 초안 작성만으로 권고안을 채택하지 않는다.
