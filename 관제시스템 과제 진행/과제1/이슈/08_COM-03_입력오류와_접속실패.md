## 목적

잘못된 접속 입력과 최초 연결 실패를 사용자가 이해할 수 있게 표시한다. 실패를 성공으로 출력하지 않고, 다음 실행에서 정상 주소로 접속할 수 있게 한다.

## 근거와 선행 조건

- 관련 기준: 기능명세 v0.7 COM-03, 요구사항정의 v0.5 R-04, 공통규칙 v0.4 C-04·C-10. 개인 실습 분할 제안이며 기존 Issue #5의 최종 완료조건을 유지한다.
- 선행: [COM03-A3](07_COM-03_CtrlC_정상종료.md)의 변경·결과 반영. 게시 시 실제 Issue URL을 연결한다.
- 먼저 익힐 내용: 입력 검사, 예외·오류 결과와 종료 코드. 확정 기한은 없고 한 작업을 확인한 뒤 다음 작업을 진행한다.

## 이번에 할 일

- 기존 접속 설정·콘솔에서 빈/공백 호스트, 포트 범위, 0 이하 접속 제한 입력을 연결 전에 거부한다.
- 기존 연결 코드에 전송 실패와 MQTT 접속 거부 결과·이유를 구분하고 비정상 종료·정리를 보완한다.
- 기존 시험 프로젝트에 입력 오류·연결 시도 없음·실패 상태 시험을 작성하고 README에 오류 예시를 기록한다.

## 진행 순서

1. 기본값과 유효한 인자는 유지하면서 호스트·포트·제한값을 검사한다. 이름 해석 실패는 입력 형식 검사와 구분한다.
2. 시험 직전 서비스가 없는 것으로 확인한 루프백 포트로 접속한다. 실제 실패 이유를 출력하고 Connected는 출력하지 않는다.
3. MQTT 접속 거부는 시험 대역으로 확인한다. 인증 기능을 새로 도입하지 않고 실패 후 올바른 주소의 새 실행도 확인한다.

## 완료조건

- [ ] 빈/공백 호스트·포트 0/65536·접속 제한 0/음수는 연결 시도 없이 이유를 표시하고 실패로 종료한다.
- [ ] 사용하지 않는 로컬 포트 접속은 원인 기록·자원 정리·비정상 종료이며 Connected가 없다.
- [ ] 시험 대역의 MQTT 접속 거부와 전송 실패를 결과에서 구분한다.
- [ ] 실패 뒤 정상 주소의 새 실행이 연결·Ctrl+C 정상 종료하고 관련 자동 시험·빌드가 성공한다.

## 시험 방법과 예상 결과

예정 시험이며 현재 결과는 미검증이다.

| 입력·절차 | 예상 결과 |
| --- | --- |
| 잘못된 인자 여섯 유형 | 입력 거부, 시험 대역 연결 호출 0, 실패 종료 |
| 서비스가 없는 것으로 확인한 포트 및 MQTT 거부 대역 | 원인 구분, Connected 없음, 정리·비정상 종료 |
| 실패 뒤 정상 주소로 새 실행 | 기존 실패와 섞이지 않고 연결·정상 종료 |

## 제외 범위

시간을 기다리는 접속 제한은 B2, 대기 중 사용자 취소는 B3이다. 새 인증 방식·연결 후 끊김·업무 메시지를 구현하지 않는다.
