## 목적

접속은 되지만 이후 Broker 응답이 전달되지 않는 시험 조건을 준비한다. 시험 환경 준비와 제품의 감지 시간 판정을 한 번에 수행하지 않도록 나눈다.

## 근거와 선행 조건

- 관련 기준: 기능명세 v0.7 COM-03, 요구사항정의 v0.5 R-04, 공통규칙 v0.4 C-04·C-09·C-10,결정사항 v0.5 D-08·D-09. 개인 실습 분할 제안이며 기존 Issue #6의 최종 완료조건을 유지한다.
- 선행: [COM03-C2](12_COM-03_Broker종료_끊김감지.md)의 변경·결과 반영. 게시 시 실제 Issue URL을 연결한다.
- 작업 구분: 후속 검증. 먼저 익힐 내용은 TCP 전달·시험용 프록시와 접속 후 응답 차단이다. 확정 기한은 없고 앞선 결과를 확인한 뒤 한 작업씩 진행한다.

## 이번에 할 일

- 사용 가능한 시험 도구를 먼저 확인해 재사용 방법과 출처를 기록한다. 없다면 생성 예정 `tools/COM-03/`에 최소 양방향 TCP 전달·응답 차단·종료 기능만 갖춘 도구를 준비한다.
- 별도 루프백 프록시 포트에서 C2의 격리 Broker로 전달한다. 정상 전달 후 Broker→Client 응답만 차단하는 조작과 로그를 마련한다.
- README에 시작·정상 전달·응답 차단·정리 절차를 기록한다. 도구 설치·방화벽 변경 대신 로컬 시험 범위에서 수행한다.

## 진행 순서

1. 도구·실행 방법을 선택하고 정상 전달 포트·대상 Broker·생성 자원을 기록한다. 새 범용 네트워크 프레임워크를 만들지 않는다.
2. 기존 콘솔을 프록시 경유로 연결해 MQTT 접속 승인을 먼저 확인한다.
3. 응답 차단 조작 후 즉시 TCP를 닫지 않으며, 차단한 응답과 연결 유지 상태를 도구 기록으로 확인한다. 감지 시간 판정은 다음 작업으로 넘긴다.

## 완료조건

- [ ] 정상 전달 상태에서 기존 콘솔이 실제 Broker 접속 승인을 받을 수 있다.
- [ ] 접속 승인 후 응답만 차단할 수 있고 TCP 즉시 종료와 다른 조건임을 기록한다.
- [ ] 도구의 조작·포트·차단 시작·생성 자원과 정리 방법을 README에서 재현할 수 있다.
- [ ] 도구 준비 결과만으로 무응답 감지 통과를 표시하지 않는다. 구현이 전달·차단·정리 범위를 넘어가면 확대하지 않고 추가 작업으로 분리한다.

## 시험 방법과 예상 결과

예정 시험이며 현재 결과는 미검증이다.

| 입력·절차 | 예상 결과 |
| --- | --- |
| 프록시 정상 전달로 실제 접속 | 접속 승인·같은 세션 ID 확인 |
| 접속 이후 응답 차단 조작 | 차단 기록·TCP 즉시 종료 아님·기존 Broker 영향 없음 |
| 시험 도구·시험 자원 종료 | 생성한 자원만 정리, 재시작 가능한 절차 |

## 제외 범위

제품 단절 감지 시간·허용 범위 판정은 C3b다. 새 MQTT 처리기·범용 프록시·PC 방화벽·보안 변경은 포함하지 않는다.
