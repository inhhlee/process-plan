## 목적

준비한 응답 차단 조건에서 연결 이상이 언제 감지되는지 측정한다. 최초 접속 제한과 연결 이후 무응답 감지를 구분한다.

## 근거와 선행 조건

- 관련 기준: 기능명세 v0.7 COM-03, 요구사항정의 v0.5 R-04, 공통규칙 v0.4 C-04·C-09·C-10,결정사항 v0.5 D-08·D-09. 개인 실습 분할 제안이며 기존 Issue #6의 최종 완료조건을 유지한다.
- 선행: [COM03-C3a](13_COM-03_무응답_시험환경.md)의 변경·결과 반영. 게시 시 실제 Issue URL을 연결한다.
- 작업 구분: 후속 검증. 먼저 익힐 내용은 장애 시작·감지 시각과 경과 시간, 감지 기준·허용 오차이다. 확정 기한은 없고 앞선 결과를 확인한 뒤 한 작업씩 진행한다.

## 이번에 할 일

- C3a 도구와 기존 콘솔·격리 Broker로 실제 무응답 시험을 수행한다.
- 시험 전에 MQTTnet 버전·KeepAlive·서버 조건·라이브러리 진단을 근거로 예상 기준·관찰 상한·허용 오차를 기록한다.
- 필요한 경우 기존 연결 감시 코드만 보완하고 새 실행 증거·README 결과를 연결한다.

## 진행 순서

1. 정상 접속 승인과 적용 설정을 기록한다. 관찰 상한·허용 오차를 실제 라이브러리·설정에 맞춰 정한다.
2. 응답 전달을 중단한 시각과 콘솔의 감지 시각을 같은 실행의 경과 시간으로 측정한다.
3. 예상 기준과 측정값을 비교하고 단절 원인·정리·종료를 확인한다. 시험 후 도구·격리 자원을 정리한다.

## 완료조건

- [ ] 접속 완료 → 응답 차단 → 연결 이상 감지의 순서·시각·측정 시간이 연결된다.
- [ ] 사전에 정한 라이브러리·설정 기준과 실제 감지 시간을 비교할 수 있다.
- [ ] 감지 뒤 상태·이유가 표시되고 자원 정리·비정상 종료한다. 단위 대역으로 실제 시험을 대체하지 않는다.
- [ ] KeepAlive 2배나 최초 접속 제한 3초를 보편적인 단절 감지 제한으로 사용하지 않는다. 실패·미검증·감지 한계와 재개 조건을 기록한다.

## 시험 방법과 예상 결과

예정 시험이며 현재 결과는 미검증이다.

| 입력·절차 | 예상 결과 |
| --- | --- |
| 정상 접속 후 응답 전달 중단 | 실제 무응답 감지와 시간 기록 |
| 사전 예상·관찰 상한·허용 오차와 비교 | 기준·측정·판정 대응. 범위 밖은 실패/미검증 사유 기록 |

## 제외 범위

자동 재접속·운영 SLA·장비 안전성 판정을 추가하지 않는다. 시험 도구 제작과 복잡한 종료 경합은 각각 C3a·C4에서 다룬다.
