- 먼저 익힐 내용: 원문 JSON을 읽는 것과 값이 유효한지 검사하는 것은 별개다. 정상 입력과 잘못된 입력을 하나씩 비교한다.

## 작업 범위와 대상

- 개발 위치: `C:\amr-control-system-demo`. 대상: Validation/·수신 모델·시험용 수신자(생성 예정), 선행 수신부, 기존 시험 프로젝트.
- 라이브러리·콘솔·시험 프로젝트는 준비돼 있다. 제품 소스는 현재 없으므로 위 모듈은 새로 만들거나 선행 작업에서 생성한 파일을 보완할 예정이며, 착수 시 실제 구조·기존 변경을 대조한다.
- 생성 예정 Validation/에서 공통데이터명세 v0.4의 Heartbeat 계약 v0.2와 수신 계약 v3를 적용한다. id·ts·status OK, Topic ID 일치, 형식·추가/중복 필드·크기/깊이 등 공통 제한을 검사한다.
- 정상 모델을 시험용 수신자(Core 대역)에 전달하고 실패는 코드·필드·이유만 남긴다. 정상/실패 결과를 반환하는 최소 경계를 만든다.
- 수신 시각은 MQTT 콜백에서 확보하되 정상 검사 후에만 함께 전달한다. Payload ts를 현재 시각으로 덮어쓰지 않는다.

1. 선행 결과와 이번 기준을 읽고 정상 입력 하나·예상 출력부터 확인한다.
2. 위 작업 범위를 순서대로 구현하거나 정리한다. 처음부터 범용 프레임워크를 만들지 않는다.
3. 아래 사례로 결과를 확인하고 실행 방법·남은 범위를 기록한다. 한 작업이 너무 크면 실제 진행 결과에 따라 나머지 범위를 분리한다.

## 완료조건

- [ ] 정상 Heartbeat는 ID·ts·status 및 수신 시각을 보존해 한 번 전달된다.
- [ ] 잘못된 입력은 이유가 기록되고 정상 수신자에게 전달되지 않는다.
- [ ] 거부 입력 다음 정상 입력을 처리하며 미처리 예외로 중단되지 않는다.
- [ ] 실제 변경·확인 결과·미검증 범위를 README와 Issue·PR에 연결한다.

## 시험 방법과 예상 결과

아래는 예정 확인이며 현재 실행 결과가 아니다.

| 입력·조건 | 예상 결과 |
| --- | --- |
| 정상 예제, ts 누락, Topic/Payload ID 불일치 | 정상만 전달, 나머지는 계약에 맞는 오류 |
| 잘못된 JSON/UTF-8·자료형·허용값·추가/중복 키·한계 초과를 자동 시험 | 각 해당 검사에서 거부. 시각 Int64 값은 자동 단위 변환 없이 보존 |
| 실제 Broker에서 오류 예제 → 정상 예제 | 오류 이후 정상 전달이 계속됨 |
