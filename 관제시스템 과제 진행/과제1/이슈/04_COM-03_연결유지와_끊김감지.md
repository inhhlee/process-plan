## 작업 범위와 대상

| 대상 | 현재 상태·작업 내용 |

라이브러리·콘솔·시험 프로젝트와 Docker 정의는 존재한다. 연결 코드·기능 시험은 이번 초안 조회 시 아직 없으며 착수 때 A~B의 실제 파일·설정과 대조한다.

- 업무 메시지 없이 적용된 KeepAlive 주기의 2배 이상 연결을 관찰한다. 제안값 5초를 적용했다면 최소 10초이며, PINGREQ/PINGRESP 또는 대응되는 라이브러리 진단·Broker 로그로 프로토콜 수준의 유지 근거를 확보한다. 단순 프로세스 실행·Connected 한 줄만으로 판단하지 않는다.
- 실제 격리 Broker 정상 종료와 접속 완료 후 서버 응답 전달 중단을 각각 시험한다. 연결 상실 상태·이유·시각을 출력하고, 한 단절당 한 번 상태 변화로 기록한다. 명시적 종료를 예상치 못한 단절로 중복 기록하지 않는다.
- 감지 시간은 실제 MQTTnet 버전·적용 KeepAlive·서버 응답·라이브러리 동작을 확인해 시험 전에 예상 기준과 관찰 상한·허용 오차를 기록하고 측정값과 비교한다. KeepAlive 2배는 유지 관찰 조건이며 모든 단절의 고정 감지 제한이 아니다. 최초 접속 제한 3초와도 구분한다.
- 콘솔의 실습 제안 동작은 예상치 못한 연결 상실을 기록하고 자원을 정리해 비정상 종료하는 것이다. 명시적 Ctrl+C 종료는 정상 종료로 구분한다. 둘이 근접하면 실제로 결정된 종료 원인·코드가 일치하고 종료가 가능해야 하며, 늦은 알림이 종료 상태를 다시 Connected로 바꾸지 않아야 한다.
- Broker 재기동 자체를 자동 복구로 표시하지 않는다. 새 프로세스의 명시적 접속 성공과 고유 Client ID로 복구 확인을 구분한다. 자동 재접속·재구독은 구현하지 않는다.

끊김 시험은 별도 이름·루프백 임시 포트를 사용하는 격리 시험용 Broker에서 수행한다. 준비한 Compose 설정·설치된 Docker·Mosquitto 이미지를 재사용하고, 실제 사용한 프로젝트명·포트·설정·생성 자원을 기록한다. 기존 사용자 Broker 및 다른 실행이 사용하는 Broker를 중단·초기화하지 않는다. 프록시는 접속 승인 후 응답 전달을 중단하고 TCP 연결을 즉시 닫지 않는 조건을 만들며, PC 방화벽·보안 설정은 바꾸지 않는다. 시험을 위해 생성한 자원은 확인한 범위에서 정리한다.

## 제외 범위

자동 재접속·재구독·대기 명령 처리(COM-06), 개별 AMR Heartbeat Timeout(COM-02), MQTT 업무 메시지 송수신, 실제 운행 State·Alarm 변경, GUI·Core·DB 및 운영 SLA·실제 장비 안전성 검증.

- [ ] 실제 격리 Broker 정상 종료 후 사전에 정한 관찰 범위 안에 연결 상실·이유·시각이 기록된다.
- [ ] 접속 후 응답 전달이 중단된 조건에서 감지 기준·허용 오차·실제 감지 시간을 비교할 수 있다.
- [ ] 같은 단절의 중복 통지와 명시적 종료를 구분하며 늦은 알림이 종료 상태를 되돌리지 않는다.
