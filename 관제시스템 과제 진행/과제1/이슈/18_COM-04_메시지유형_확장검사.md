### 적용할 계약

공통으로 대소문자를 구분하는 `amr/{amrId}/{kind}` Topic, ID 규칙, strict UTF-8 JSON object, 추가·중복 필드·주석·후행 쉼표 거부, 65,536 bytes·깊이 16 제한을 A와 동일하게 사용한다. ID는 비어 있거나 공백·제어 문자·`/`·`+`·`#`를 포함할 수 없으며 Unicode ID는 정규화하지 않는다.

| 유형 | 필수·선택 필드와 규칙 |
| --- | --- |
| Telemetry | 필수 `id, ts, pos{x,y}, sp, state`. pos는 x/y만 허용하며 x/y는 유한 double, sp는 유한 double·0 이상. 개발 단위 m·m/s. state는 `IDLE/BUSY/STOPPED/FAULT` |
| Alarm | 필수 `id, ts, code, level, alarmState`, 선택 `message`. level은 `INFO/WARN/ERR/FATAL`, alarmState는 `ACTIVE/CLEARED`. 문자열 값은 모델에서 의미를 보존하며 실제 AMR State를 변경하지 않음 |
| ACK | 필수 `cmdId, result, ts`, 선택 `id, reason`. result는 `SUCCESS/FAILURE`. id가 있을 때만 Topic ID와 일치 검사. reason 없는 기존 형식도 허용하며 있으면 그대로 보존 |

- `id, cmdId, code`와 선택 `message, reason`은 존재할 때 null·빈 문자열·공백만인 문자열을 거부한다. 필수 id는 Topic ID와 정확히 일치해야 한다.
- `ts`는 signed Int64 JSON 정수이고 문자열·소수·지수 표기를 거부한다. Int64 전체 범위를 자동 단위 변환 없이 보존한다.
- 선택 필드는 생략 가능하지만 존재하면 자료형·허용값을 검사한다.
- 유효한 `FAILURE` ACK도 정상 모델로 반환한다. 검증 실패로 폐기하거나 `SUCCESS`로 바꾸지 않는다. 실제 명령 업무 결과 판단은 Core 담당이다.
- 실패 결과는 Code·Field·Reason으로 기록할 수 있어야 하며 원문 Payload를 오류 로그에 남기지 않는다.

1. 선행 A의 검사·모델·실패 결과와 실제 시험 근거를 확인한다.

5. 기존 Heartbeat 결과와 공통 오류 처리 경계를 회귀 확인하고 기록한다.
