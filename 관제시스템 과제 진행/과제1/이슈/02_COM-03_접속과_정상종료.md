## 목적

준비 콘솔에 실제 MQTT Broker 접속을 구현한다. Broker의 접속 승인 뒤에 연결 상태를 표시하고, Ctrl+C로 연결·자원을 정리한 뒤 새 실행으로 다시 접속할 수 있게 한다.

## 작업 범위와 대상

| 대상 | 현재 상태·작업 내용 |
| --- | --- |
| `src/Amr.Communication/` | 기존 라이브러리·MQTTnet 5.2.0.1603 참조 유지. 생성 예정 `Mqtt/`에 접속 설정·연결·명시적 종료와 자원 정리 구현. 실제 라이브러리 호출을 시험 대역으로 대체할 최소 경계 마련 |
| `src/Amr.Communication.Console/Program.cs` | 기존 준비 출력을 접속 요청·결과·Ctrl+C 취소 및 종료 처리로 보완 |
| `tests/Amr.Communication.Tests/` | 기존 xUnit 프로젝트에 정상 접속·명시적 종료·자원 해제 동작 시험 추가. 시험 파일은 생성 예정 |
| `docker/compose.yaml`, `docker/mosquitto/config/mosquitto.conf` | 준비한 `amr-demo / mosquitto` 설정을 사용해 실제 기동·호스트에서의 MQTT 접속 확인. 설정 변경이 필요하면 원인·영향을 기록 |
| `README.md`, `evidence/COM-03/<실행ID>/` | 실제 콘솔 인자·명령·상태 의미·종료 방법과 새 실행 증거 작성. COM-03 증거 경로는 생성 예정 |

개발용 제안 설정은 호스트 `127.0.0.1`, 포트 `1884`, MQTT 5, Clean Start, 실행마다 고유 Client ID, KeepAlive 5초, 최초 접속 대기 제한 3초다. 호스트·포트·접속 대기 제한은 실행 인자로 지정할 수 있게 하고 적용 설정·Client ID를 출력·README·증거에 남긴다. 기존 1883 Broker나 기존 프로그램의 Client ID를 사용하지 않는다. 패키지를 임의로 최신화하지 않는다.

연결 요청 중과 실제 연결됨, 명시적 종료 후를 구분한다. 성공한 MQTT 접속 승인을 받은 뒤에만 `Connected`를 출력한다. 연결된 콘솔은 Ctrl+C까지 유지하고, 종료 요청 시 연결 정리를 기다린 뒤 종료 코드 0으로 끝내며 자원을 해제한다. 최초 접속 실패를 성공으로 숨기지 않는 최소 처리도 포함한다. 오류 종류·입력 경계·접속 중 취소의 상세 검증은 COM03-B에서 보완한다.

이번 실제 시험에서는 준비한 프로젝트 전용 Broker의 기동·상태·로그를 확인한다. 포트 사용·Docker·이미지·마운트 문제를 MQTT 소스 실패와 구분한다. 기존 사용자 Broker를 중단·초기화하지 않으며 SDK·Docker·Broker를 새로 설치하지 않는다. 새 Broker가 실행되지 못하면 실제 접속 시험을 미검증으로 남기고 환경 원인·재개 조건을 기록한다.

## 제외 범위

MQTT 메시지 구독·발행, 가상 AMR·개별 Heartbeat, 연결 후 무응답·끊김 감지의 상세 시험(COM03-C), 자동 재접속·재구독(COM-06), GUI·Core·DB와 운행 State·Alarm 판단.
