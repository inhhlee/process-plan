## 목적

정상 Heartbeat를 보낸 AMR이 중단됐는지 판정하고 다시 보내면 복구를 알린다.

## 작업 범위와 대상

- 개발 위치: `C:\amr-control-system-demo`. 대상: Monitoring/와 감시 이벤트(생성 예정), 선행 정상 Heartbeat 전달 경계, 콘솔·시험.
- 라이브러리·콘솔·시험 프로젝트는 준비돼 있다. 제품 소스는 현재 없으므로 위 모듈은 새로 만들거나 선행 작업에서 생성한 파일을 보완할 예정이며, 착수 시 실제 구조·기존 변경을 대조한다.
- 생성 예정 Monitoring/에서 DN-10의 첫 정상 Heartbeat부터 감시, 기본 Timeout 5초·확인 주기 0.5초·경과 >= Timeout 기준을 적용한다.
- 수신 UTC와 단조 시계 경과 시간을 구분한다. Payload ts·처리 완료 시각 대신 검사 전 확보한 정상 메시지의 수신 시각을 사용한다.
- 중단 구간당 Timeout 한 번, 정상 수신 재개 시 복구 한 번을 통지한다. 기존 개발 계약을 다시 미정으로 두지 않는다.

## 진행 순서

1. 선행 결과와 이번 기준을 읽고 정상 입력 하나·예상 출력부터 확인한다.
2. 위 작업 범위를 순서대로 구현하거나 정리한다. 처음부터 범용 프레임워크를 만들지 않는다.
3. 아래 사례로 결과를 확인하고 실행 방법·남은 범위를 기록한다. 한 작업이 너무 크면 실제 진행 결과에 따라 나머지 범위를 분리한다.

## 완료조건

- [ ] 첫 정상 수신 전에는 해당 AMR을 감시 대상으로 등록하지 않는다.
- [ ] 경계 직전/경계 도달 결과가 다르고 중단 구간당 한 번 통지된다.
- [ ] 불량 Heartbeat·다른 유형은 생존 시각을 갱신하지 않는다.
- [ ] 정상 수신 재개 시 한 번 복구되며 이후 새 중단을 감지한다.
- [ ] 실제 변경·확인 결과·미검증 범위를 README와 Issue·PR에 연결한다.

## 시험 방법과 예상 결과

아래는 예정 확인이며 현재 실행 결과가 아니다.

| 입력·조건 | 예상 결과 |
| --- | --- |
| 제어 가능한 시계로 Timeout 직전·동일·초과 | >= 경계에서 한 번 통지 |
| Payload ts 과거/미래, 불량 입력, Telemetry만 전송 | 정상 Heartbeat의 실제 수신만 갱신 |
