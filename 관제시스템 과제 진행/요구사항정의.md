## 1. 프로젝트 범위와 근거

프로젝트 목표는 Windows Application 기반 가상 AMR과 기초 관제 시스템을 구성하는 것이다. MQTT 통신을 통해 이동·상태·알람·명령 응답을 연결하고 GUI에서 모니터링과 제어가 가능하도록 한다. Core는 장비·최신 상태·알람·명령·이력을 처리하며 SQLite는 상태 변경·알람·명령 결과·운행 이력을 저장한다.

### 1.1 자료별 역할

- [책임님 원문](<C:/Users/north/Downloads/가상 AMR_관제 시스템 단계별 개발 과제 구성.pdf>): 본문 작성일은 2026-09-04이며 버전 표기는 없다. 2쪽의 개발 목표·구성요소·SQLite 저장 범위와 3쪽의 공통 결과물·과제 1~5를 개발 범위의 기준으로 사용한다.
- [요구사항 초안 v0.0](<C:/Users/north/Downloads/261001_SI생태계_요구사항 정의서_이인호 연구원_v0.0 (2).hwp>): v0.0은 파일명 기준이다. 본문의 공통 문서 초안(R-01~R-07), 공유규칙(11개), 정의 공유 규칙의 임시 채택값 및 결정이 필요한 부분을 참고한다.
- 기존 기능명세 v0.3 — 원본 미제공·재대조 미완료: COM·AMR·GUI·CORE·INT 기능 ID와 데이터·Topic 예시의 기존 참고 기록을 보존한다. 원문 재대조 전에는 현재 확인된 근거나 확정 요구로 취급하지 않으며 상충하는 정의는 결정 항목으로 관리한다. 원본 식별 정보는 [Agent 업무 규칙](AGENTS.md)의 자료 표를 참조한다.

- 원문 연결 갱신(2026-10-05): 사용자가 제공한 PDF·HWP로 기존 경로를 교체하고, 제공본에서 확인되지 않은 PDF의 v0.2 표기를 제거했다. 이 변경은 원문 식별과 연결 보완이며 전체 명세 검토 완료나 설계 확정을 의미하지 않는다.

### 1.2 근거와 상태 구분

- **원문 요구**는 책임님 자료에 명시된 기능 범위와 결과물이다. R-01~R-07은 해당 내용을 기존 초안의 ID로 요약한 것이다.
- **설계 제안**은 기존 초안 또는 이번 정리에서 요구를 구현하기 위해 구체화한 방식이다. 문서에 기재되어 있다는 이유로 확정하지 않는다.
- **임시 채택**은 기존 초안에서 개발용으로 임시 사용한 값이다. 최종 정책과 구분한다.
- **미정**은 선택과 상세 정의가 필요한 항목이다. D-01~D-12에 영향 범위와 후속 작업을 기록한다.
- 검토 후 결정된 항목만 확정으로 바꾸고 결정 근거를 남긴다. 요구사항의 검토, 설계 결정, 구현 완료 및 검증 통과는 각각 별도로 기록한다.

## 2. 공통 요구사항

R-05에는 원문 결과물인 DataProvider 인터페이스를 명시하여 기존 요구사항 초안의 표현을 보완했다. SQLite의 운행 이력 저장 범위는 R-06 및 CORE-05에 연결했다. 아래 문장은 원문 요구의 요약이며 수치·프로토콜 상세값을 확정하는 문장이 아니다.

### R-01

- 요구사항: 가상 AMR·통신·GUI·관제 핵심 기능을 연결하여 기초 관제 동작을 제공한다.
- 원문 근거: 책임님 자료의 개발 목표, 과제 1~5 결과물, 과제5
- 적용 과제: 과제1~5
- 관련 기능: [COM-01](기능명세.md#com-01-실시간-메시지-송수신)~06, [AMR-01](기능명세.md#amr-01-설정-로드와-amr-생성)~05, [GUI-01](기능명세.md#gui-01-대시보드)~05, [CORE-01](기능명세.md#core-01-장비-등록과-조회)~05, [INT-01](기능명세.md#int-01-정상-운행과-표시-검증)~04
- 확인 기준: 연결된 실행본에서 INT-01~04의 계획된 동작을 확인한다.

### R-02

- 요구사항: 가상 AMR은 좌표 이동, 상태 변경, 알람 발생 및 명령 응답을 제공한다.
- 원문 근거: 책임님 자료의 전체 개발 내용, 과제2
- 적용 과제: 과제2
- 관련 기능: [AMR-02](기능명세.md#amr-02-command-수신과-동작-수행)~05; [INT-01](기능명세.md#int-01-정상-운행과-표시-검증)~03
- 확인 기준: 독립 시뮬레이터에서 이동·상태·알람·응답 결과를 확인한다.

### R-03

- 요구사항: AMR 수량·초기 좌표·속도·이동 경로·장애 시나리오는 설정 파일로 변경한다.
- 원문 근거: 책임님 자료의 과제2 설명
- 적용 과제: 과제2
- 관련 기능: [AMR-01](기능명세.md#amr-01-설정-로드와-amr-생성)~03; [INT-01](기능명세.md#int-01-정상-운행과-표시-검증), [INT-03](기능명세.md#int-03-alarm-발생과-해제-검증)
- 확인 기준: 코드 수정 없이 설정을 변경하여 시험 조건이 달라지는지 확인한다.

### R-04

- 요구사항: 통신 계층은 MQTT 접속 관리·재접속·Heartbeat·명령/응답·메시지 유효성 검사를 제공한다.
- 원문 근거: 책임님 자료의 과제1 설명 및 콘솔 시험 결과물
- 적용 과제: 과제1
- 관련 기능: [COM-01](기능명세.md#com-01-실시간-메시지-송수신)~06; [INT-02](기능명세.md#int-02-command-전체-흐름-검증), [INT-04](기능명세.md#int-04-통신-이상과-복구-검증)
- 확인 기준: 콘솔에서 정상 송수신, 연결 끊김, 재접속 및 메시지 검증을 확인한다.

### R-05

- 요구사항: GUI는 요구사항·기능명세를 기반으로 구성하고 Mock AMR로 실행하며 DataProvider 인터페이스를 제공한다.
- 원문 근거: 책임님 자료의 과제3 설명 및 결과물
- 적용 과제: 과제3
- 관련 기능: [GUI-01](기능명세.md#gui-01-대시보드)~05; [INT-01](기능명세.md#int-01-정상-운행과-표시-검증)~03
- 확인 기준: Mock 공급자로 화면을 실행하고 같은 인터페이스로 Core 공급자에 연결한다.

### R-06

- 요구사항: GUI와 통신 사이의 핵심 서비스 계층은 장비·최신 상태·알람·명령·이력을 처리한다.
- 원문 근거: 책임님 자료의 전체 개발 내용, 과제4
- 적용 과제: 과제4
- 관련 기능: [CORE-01](기능명세.md#core-01-장비-등록과-조회)~05; [GUI-01](기능명세.md#gui-01-대시보드)~05
- 확인 기준: 처리 라이브러리의 입력과 결과를 개별 시험으로 확인한다.

### R-07

- 요구사항: 각 모듈의 처리 결과를 확인하고 연결 후 시나리오로 전체 동작을 검증한다.
- 원문 근거: 책임님 자료의 과제4 결과 검증, 과제5 모듈 연결 및 시나리오 검증
- 적용 과제: 과제4~5 및 개별 시험
- 관련 기능: [CORE-01](기능명세.md#core-01-장비-등록과-조회)~05; [INT-01](기능명세.md#int-01-정상-운행과-표시-검증)~04
- 확인 기준: 개별 시험과 통합 시나리오에 예상 결과·실제 결과·판정을 기록한다.
