# 가상 AMR 관제 시스템 전체일정

- 문서명: 가상 AMR 관제 시스템 전체일정
- 작성자: Codex 작성 보조
- 작성일: 2026-10-02
- 수정일: 2026-10-07
- 버전: v0.11 초안
- 프로젝트: 가상 AMR + 관제 시스템
- 프로젝트 최종 기한: 미정

이 문서는 공통 요구사항 정리와 과제 1~5의 목표, 주요 결과물, 일정 및 진행 상태를 관리한다. 공통 요구사항·기능명세와 과제별 계획 초안을 작성했으며 사용자 검토를 기다리고 있다. 2026-10-05에 기존 코드 `C:\practice`를 확인하여 과제1을 진행 중으로 정정했다. 개발환경의 기본 검증은 통과했으며 과제별 전체 완료 검증은 미완료다.

2026-10-07 사용자는 프로젝트를 신입 개발자 한 명이 진행한다고 알려주었다. 실제 실습 위치는 `C:\amr-control-system-demo`, 문서 원본은 `C:\process-plan`이다. 새 저장소의 준비 #2·PR #3은 완료했고 기능 구현은 아직 없다. 기존 `C:\practice`의 부분 통과 기록과 새 실습의 진행 상태를 구분한다. 아래 1인 개발 순서는 작업 분할 제안이며 새로운 납품 기한이나 전체 완료 승인이 아니다.

## 1. 프로젝트 목표

Windows Application 기반으로 가상 AMR과 기초 관제 시스템을 구성한다. 가상 AMR의 이동, 상태 변경, 알람 및 명령 응답을 MQTT 통신으로 관제 시스템과 연결하고, GUI에서 모니터링과 제어가 가능하도록 한다. 관제 핵심 기능은 장비, 최신 상태, 알람, 명령 및 이력을 처리하고 SQLite에 필요한 업무 이력을 저장한다.

최종 결과물은 과제 1~4의 구성요소를 연결한 가상 AMR 기반 기초 관제 시스템 실행본이다. 전체 동작은 과제 5의 시나리오 시험으로 확인한다.

## 2. 일정과 상태의 초기 기준

- 과제 1~5의 개발 시작 예정일과 완료 기한은 미정이다. 기존 과제1의 실제 개발 착수일은 별도 확인이 필요하며, 2026-10-05는 기존 코드 확인일이다. 2026-10-02는 문서 작성일이며 공통 초안 정리의 착수일이다.
- 공통 명세 정리는 진행 중이며 초안 작성 완료·사용자 검토 대기 상태이다. 과제1은 기존 코드의 부분 구현을 확인했다. 과제2~5는 기존 미착수 표시를 유지하되 실제 코드와 전체 범위의 대조는 아직 수행하지 않았다.
- 참고 문서는 기존 초안으로 활용하며, 문서가 존재한다는 이유로 명세 검토나 개발을 완료로 처리하지 않는다.
- 작업 상태는 미착수, 진행 중, 완료로 구분하고 검증 상태는 별도로 기록한다.
- 상세 설계값은 원문 요구, 설계 제안, 임시 채택, 미정 등의 구분을 유지한다.
- 새 실습은 한 사람이 한 작업의 학습·구현·필요한 시험·PR 검토를 마친 뒤 다음 작업으로 진행한다. 여러 과제를 동시에 개발하는 인력 계획을 가정하지 않는다. 소요 시간은 첫 작업의 실제 기록을 보고 추정하며 확정 기한 없이 하루 완료를 약속하지 않는다.

## 4. 작업 순서 초안

아래는 과제 전체의 단계 구분과 기존 코드 재사용 계획이다. 기존 `C:\practice` 개발 순서는 [MVP M1-00~05](<C:/practice/docs/mvp/happy_path_plan.md>)의 정상 화면 시연 우선 계획과 연결한다. 새 실습에서 이 구현·순서를 자동으로 복사하지 않는다. 이 순서를 과제1의 자동 재접속 요구 삭제나 사수의 납품 순서 변경 승인으로 해석하지 않는다.

1. 공통 요구사항과 기능명세를 정리하고 개발환경의 준비 상태를 확인한다.
2. 과제1의 기존 송수신·입력 검사·Broker/Heartbeat 감시를 재사용하고, COM-05의 전체 요청/응답 검증과 COM-06의 자동 재접속을 남은 범위로 관리한다.
3. 공통 데이터와 인터페이스를 기준으로 과제2의 가상 AMR, 과제3의 Mock GUI, 과제4의 핵심 기능을 구현하고 각각의 결과를 확인한다. 세부 작업 순서는 각 과제계획에서 정한다.
4. 과제5에서 구성요소를 연결하고 정상 운행, 명령, 알람 및 통신 이상 시나리오를 검증한다. 이 시나리오 구분은 초기 시험 구성 제안이다.

기능별 수는 COM-01 3개, COM-02 2개, COM-03 3개, COM-04 2개, COM-05 2개, COM-06 3개, 전체 검증 1개다. COM-01/04는 한 종류 수신 → 검사 → 다른 유형 검사 → 다중 수신으로 번갈아 진행한다. COM-06에는 미정인 복구 정책을 선택하는 작업이 포함된다. 정책·기간을 임의 확정하지 않는다.

기존 COM-03 #4·#5·#6은 그대로 구현 Issue로 활용한다. 앞선 11개 세부 문서는 각 Issue의 학습·확인 단계로 보존하며 새 11개 Issue로 일괄 게시하지 않는다. 무응답 도구·수신 큐처럼 진행이 큰 부분은 실제 학습·개발 결과를 보고 추가 분리한다. 처음 확인할 결과를 작게 잡는 것이며 어려운 필수 완료조건을 삭제하지 않는다.

현재 변경은 과제1 전체 계획·초안이다. 기존 GitHub 본문·관계는 바꾸지 않았고 새 초안도 게시하지 않았다. 과제2~5의 상세 Issue는 각 과제의 선행 결과·계약을 확인해 작성한다.

## 5. 현재 결과와 다음 작업

첫 작업인 공통 초안 및 과제계획 작성은 완료했다. 사용자 내용 검토와 설계 결정은 대기 상태이다.

- [요구사항정의](명세/요구사항정의.md)에 R-01~R-07과 프로젝트 범위·원문 결과물을 정리했다.
- [공통규칙](명세/공통규칙.md)에 C-01~C-11을, [공통데이터명세](명세/공통데이터명세.md)에 데이터 의미·메시지·임시값을 정리했다.
- [기능명세](명세/기능명세.md)에 기능 25개를, [검토 및 결정사항](명세/검토%20및%20결정사항.md)에 D-01~D-12와 후속 작업을 정리했다.
- 기존 통합 문서는 [명세 문서 안내](../README.md#specifications)로 구성하여 각 명세에 연결했다.
- 과제 1~5의 계획 초안에 목표·작업 순서·산출물·시험 계획·완료 기준을 작성했다.
- 2026-10-05: 사용자 요청에 따라 과제 1~5의 계획을 [개발계획 작성 규칙](../기준/개발계획%20작성%20규칙.md)의 8개 절로 통일하고 HTML 보기본을 연결했다. [양식 적용 변경보고](../보관/변경보고/개발계획%20양식%20적용%20변경보고.md)에서 반영 범위와 확인 결과를 관리한다. 이는 문서 양식 정리이며 개발·검증 상태는 유지한다.
- 2026-10-05: 기존 코드 저장 위치를 `C:\practice`로 확인하고 개발환경·기본 실행을 점검했다. 기존 ‘과제1 미착수’ 표기를 진행 중으로 정정했다. 코드 저장소의 기능 추적기·임시 계약과 현재 문서 간 차이 및 후속 정리는 [결정사항의 이번 COM-01 작업 영향과 후속 정리](명세/검토%20및%20결정사항.md#com01-readiness)에서 관리한다.
- 기능명세와 과제계획의 시험 표는 전체 범위를 확인하기 위한 계획이다. 이번 개발환경 점검 및 저장소의 과거 기능 검증 기록과 구분한다.

2026-10-05 준비 보완: 환경 기준과 실제 검증결과·일일업무를 분리하고, 기본 코딩 규칙·Heartbeat 임시 계약과 예제·이번 대상 파일과 판정 조건·빈 기록 양식을 연결했다. [준비 항목과 근거](../일일업무/2026-10-05.md)에서 확인한다.

2026-10-06 문서 연결 보완: 세 명세 문서의 오래된 미착수 표현을 정리하고, 작성 예시·기능명세 위치 안내·자료조사 양식을 구분했다. [과제1 주간 기록](과제1/주간/2026-10-05_10-09.md)에 확인된 일일업무와 산출물을 연결했다. 변경 근거와 확인 결과는 [2026-10-06 일일업무](../일일업무/2026-10-06.md#document-links)에서 관리한다.

2026-10-06 기준 정합성 보완: 현재 코드의 기존 채택 계약과 COM-01~04 passing·COM-05 not_started 기록을 과제1 계획에 연결했다. Heartbeat 예제의 status 누락·수신 옵션·입력 경로와 오래된 구현 설명을 정정했다. 기존 실행 증거를 읽은 결과이며 제품 재시험은 하지 않았다. [변경보고](../보관/변경보고/2026-10-06_과제1_기준정합성_변경보고.md)에서 확인한다.
