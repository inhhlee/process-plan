# 가상 AMR 관제 시스템 AI 기본 규칙

[저장소 공통 지침](../AGENTS.md)에 더해 관제 프로젝트의 문서·계획·구현·검증 기록에 적용한다.

## 범위와 근거

- 과제1~5를 하나의 프로젝트로 관리하고 과제별 작업을 프로젝트 목표·관련 기능 ID에 연결한다.
- 기본 개발 범위와 결과물은 [요구사항정의의 원문 자료](명세/요구사항정의.md#11-자료별-역할)를 따른다. 원문 파일명·버전·페이지·제공 상태는 해당 문서에서 관리한다.
- 기존 HWP의 상세값·예시를 책임님 PDF의 확정 요구로 취급하지 않는다. 미제공 v0.3에서 유래한 기록은 원문 재대조 전까지 확인된 요구로 격상하지 않는다.
- 원문에 없는 처리·확인 방법은 설계·시험 제안으로 표시한다. 사용자 추가·변경은 원문 요구와 구분해 근거를 남긴다. 원본 자료 수정은 요청받은 경우에 수행한다.

## 문서와 작업 선택

- [명세 문서 안내](../README.md#specifications)에서 담당 문서를 찾고 요청과 관련된 R·C·데이터·기능·D·과제계획의 현재 내용을 읽는다. 공통 기능 정의는 명세 폴더의 [기능명세](명세/기능명세.md)가 담당한다.
- 기존 ID를 유지한다. 추가·분리 시 원문 요구를 드러내기 위한 것인지 새 제안인지 이유와 연결을 남긴다.
- 명세 작성·검토는 [amr-feature-spec](../.agents/skills/amr-feature-spec/SKILL.md), 계획 작성·검토는 [plan-development](../.agents/skills/plan-development/SKILL.md), 구현·시험은 [amr-implement-verify](../.agents/skills/amr-implement-verify/SKILL.md)를 적용한다. 실제 결과를 정리할 때는 [record-work](../.agents/skills/record-work/SKILL.md)를 사용한다.
- 실제 코드 저장소의 지침과 구현을 확인해 기술·폴더·명명·오류 처리·실행 방법을 적용한다. 실습자료의 기술이나 현재 COM-01의 제한된 조건을 다른 기능에 자동으로 적용하지 않는다.

## 결정과 검증

- 충돌과 미정 정책은 [검토 및 결정사항](명세/검토%20및%20결정사항.md)에 원본 위치·영향 기능·선택지·제안 이유·후속 작업을 연결한다. 요청과 이미 기록된 결정으로 정할 수 있는 범위는 적용하고, 새 사용자 판단이 필요한 사항을 구체화한다.
- 결정 후 영향받는 규칙·데이터·기능명세·계획을 갱신하고 결정 주체·근거를 남긴다. 임시 적용 범위를 운영 확정으로 확대하지 않는다.
- 근거 기록과 상태·완료 정의는 [공통 작성 규칙](../기준/공통%20작성%20규칙.md)을 적용한다. 개별 과제와 과제5 통합 검증, 과제3의 Mock·DataProvider 시험과 실제 Core 연계를 구분해 보고한다.
- 문서 준비 완료와 실제 구현·시험 완료를 구분한다. 변경한 문서의 본문·링크·ID·상태를 확인하고 제품 결과는 실제 실행 근거로 판단한다.
