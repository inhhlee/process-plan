## 3. 사용할 개발환경

버전은 최신 권장값을 새로 고른 것이 아니라 현재 저장소와 PC에서 확인한 값이다.

| 항목 | 확인한 구성 | 판정과 확인 범위 |
| --- | --- | --- |
| 운영체제 | Windows x64, 빌드 26200.9457 | 현재 PC에서 점검 |
| 개발 도구 | Visual Studio Community 2026, 18.10.2 | 설치와 .NET 데스크톱 개발 워크로드 확인. IDE 화면 실행은 별도 |
| 언어·플랫폼 | C# / .NET SDK 10.0.401 | `global.json`과 일치. 콘솔·라이브러리는 `net10.0`, WPF는 `net10.0-windows` |
| PowerShell | Windows 등록본 7.6.6, 이번 검증 실행본 7.6.5 | 둘 다 실행 확인. `init.cmd` 요구 조건은 7.4 이상 |
| Git | 2.42.0.windows.2 | 저장소 상태와 코드 버전 조회 통과 |
| MQTT 라이브러리 | MQTTnet 5.2.0.1603 | 프로젝트 패키지 정의와 빌드 확인 |
| Docker | Desktop 4.91.0 / Engine 29.8.0 | `desktop-linux` 엔진 연결 확인 |
| 개발 Broker | `eclipse-mosquitto:2.1.2-alpine` / `amr-mosquitto` | 기존 컨테이너 실행, `127.0.0.1:1883` 연결·구독 통과 |
| 로그 관찰 서비스 | `datalust/seq:2026.1` / `amr-seq` | 기존 컨테이너와 localhost 5341 포트 매핑 확인. 화면·로그 유입은 미검증 |
| MQTT Explorer | 설치 등록과 표준 경로에서 미확인 | 이동식 설치 여부 미확인. 이번 콘솔 접속 시험에는 사용하지 않음 |

위 설치 버전은 2026-10-05 점검 당시 값이다. 코드의 SDK·패키지 기준은 `global.json`과 프로젝트 파일을 우선 확인한다. WPF·Seq의 상세 실행 검증은 해당 기능을 다룰 때 수행한다. 이번 최소 송수신은 기존 콘솔과 Mosquitto 발행 도구를 사용하므로 MQTT Explorer 설치를 선행 조건으로 두지 않는다.

## 4. 실행 순서

Visual Studio에서 위 솔루션을 연다. 일반 준비·검증은 코드 저장소의 표준 진입점을 사용한다.

```powershell
Set-Location C:\practice
.\init.cmd check
.\init.cmd verify
```

실제 MQTT 작업 시 Docker Desktop과 개발 Broker를 확인한다. Broker가 준비되지 않았다면 다음 표준 명령을 사용한다.

```powershell
.\init.cmd broker
.\init.cmd start -DurationSeconds 5
```

`Connected`와 `Subscribed: amr/+/heartbeat`는 접속·구독 결과다. 최소 송수신의 발행·수신·오류 입력 절차와 판정은 [과제1 계획](과제1/과제계획.md#com01-test)에 따른다. `verify-broker`는 Broker 장애 등 별도 시험용이며, 문서 정리만으로 반복 실행하지 않는다.
