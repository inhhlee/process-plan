# 업무 계획·명세·기록

가상 AMR 관제시스템 과제1~5의 기준·명세·계획·실제 결과를 관리합니다. 이 README에서 필요한 담당 문서를 찾아 읽고 같은 내용을 여러 문서에 반복해서 작성하지 않습니다.

## 처음 읽는 순서

1. [전체일정](관제시스템%20과제%20진행/전체일정.md)에서 과제별 기한·상태와 대상 계획을 확인합니다.
2. 아래 [명세 안내](#specifications)에서 이번 작업과 관련된 요구·동작·계약·결정만 읽습니다.
3. 계획을 작성할 때는 [작성 기준과 양식](#문서를-작성할-때), 개발을 시작할 때는 [개발 진행 절차](기준/개발%20진행%20절차.md)를 확인합니다.
4. 실제 결과는 [일일업무](일일업무/)와 과제별 주간 기록·산출물에서 확인합니다.

기존 문서를 먼저 갱신하고 새 결과에만 양식을 복사합니다. 복사할 때 상대 링크를 저장 위치에 맞춥니다. 일반 문서 수정은 필요한 업무 요약만 남기며, 별도 설명·제출이 필요한 변경에만 변경보고를 작성합니다. 구체적인 구분은 [공통 변경 기준](기준/공통%20작성%20규칙.md#changes)을 따릅니다.

## 실제 작업 흐름

명세 → 계획 → 구현·검증 → 업무 기록 중 현재 필요한 단계부터 요청합니다. 예: “과제2의 첫 작업 계획만 기존 과제계획에 반영해줘”, “선택한 Issue를 구현하고 실제 검증 근거를 알려줘”, “오늘 수행한 결과를 기존 일일·주간 기록에 요약해줘”. 문서 정리만 요청한 경우 제품 구현·시험·외부 보고까지 범위를 넓히지 않습니다.

## GitHub 협업을 함께 사용할 때

상세 순서와 요청문은 [개발 진행 절차](기준/개발%20진행%20절차.md)에서 관리합니다. 명세·계획을 Issue에 연결하고 구현·검증 결과를 PR에 연결합니다. 실제 코드 저장소의 origin·기본 브랜치·기존 변경·협업 규칙·사용 가능한 권한을 확인합니다. 작업 순서는 Issue 번호가 아닌 의존성·우선순위를 따르며 세부 작업·리뷰는 Issue·PR에, 업무 기록에는 결과 요약과 링크를 남깁니다.
