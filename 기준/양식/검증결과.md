# 검증결과 기능ID 시험명 실행ID

- 작성자·실행자: 미작성
- 문서 구분: 빈 양식 — 시험별 실제 기록을 작성할 때 복사
- 저장 위치: 해당 과제의 `산출물/YYYY-MM-DD_기능ID_시험명_실행ID_검증결과.md`
- 관리 방법: 실행별 결과를 보존. 재시험은 새 실행 ID를 사용하고 이전 실패·미실행 기록 유지

## 1. 목표와 적용 기준

- 프로젝트·과제·기능 ID: 미작성
- 확인할 범위: 미작성
- 이번에 확인하지 않는 범위: 미작성
- 관련 명세·계약 버전·결정사항·계획 링크: 미작성
- 코드 추적기의 spec_revision·verification_index: 미작성 또는 해당 없음과 이유
- 기대하는 성공 조건: 미작성

## 2. 실행 환경

| 항목 | 실제 값 |
| --- | --- |
| 실행 ID | 미작성 |
| 실행 시작·종료 시각과 시간대 | 미작성 |
| PC·OS·SDK·라이브러리 | 미작성 |
| 코드 저장 위치·Git 커밋·미커밋 변경 | 미작성 |
| Broker 종류·버전·주소·포트 | 미작성 |

| 실제 구성요소·테스트 대역 | 미작성 |
| 증거 저장 경로 | 미작성 |

인증정보는 작성하지 않는다. 과거 환경값을 확인 없이 복사해 현재 값으로 기록하지 않는다.

## 4. 실제 결과와 판정

| 시험 ID | 실제 결과 | 판정 | 로그·화면·TRX 등 증거 |
| --- | --- | --- | --- |
| 미작성 | 미실행 | 미검증 | 미작성 |

판정은 미검증·검증 중·통과·실패를 사용한다. 코드 추적기에 옮길 때 통과는 `passed`, 실패는 `failed`, 미실행은 `not_run`으로 대응한다. 실행되지 않은 시험을 통과로 표시하지 않는다.
