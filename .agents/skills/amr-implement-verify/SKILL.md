# 관제 기능 구현·검증

## 시작 자료

[프로젝트 지침](../../../관제시스템%20과제%20진행/AGENTS.md), 해당 과제계획의 이번 작업·시험, 관련 R·C·데이터·기능·D, [환경·코드 위치 안내](../../../관제시스템%20과제%20진행/개발환경.md)를 확인한다. 환경 안내의 경로·과거 점검 결과는 현재 저장소와 대조한다.

## 수행 방법

1. 사용자가 지정한 기능·범위·완료 조건을 확인한다. 실제 코드 저장소에서 적용되는 지침, 현재 변경, 진행 기록·추적기, 구현·계약·실행 방법을 읽는다. 기존 진행 작업과 요청이 다르면 범위와 영향을 구분한다.
2. 과제계획에 대상 파일·모듈·변경 내용·선행 결정·시험 입력·예상 결과가 구체적인지 확인하고 필요한 부분을 보완한다. 기술·폴더·오류 처리·빌드 기준은 실제 저장소를 따른다. [기본 코딩 규칙](../../../관제시스템%20과제%20진행/개발환경.md#coding-rules)의 COM-01 적용 범위를 다른 기능에 확대하지 않는다.
3. 미정 정책의 영향부터 판단한다. 요청과 기존 결정으로 가능한 작업을 수행하고 사용자 판단이 필요한 사항은 선택지·영향까지 정리한다. 한 기능의 임시 선택을 운영 정책으로 확정하지 않는다.
4. 해당 변경에 필요한 기준선과 기존 동작을 확인한다. 이미 성공한 검증을 코드·환경·계약 변경이나 새로운 우려 없이 반복하지 않는다. 기존 동작이 요청 조건을 만족하면 증거를 남긴다. 보완이 필요한 경우 원인을 환경·입력·관련 모듈로 구분하고 해당 범위만 수정한다.
5. 수정 후 관련 빌드·시험과 영향받는 회귀 검증을 수행한다. 실제 MQTT·DB·GUI 연동이 완료 기준에 포함되면 해당 연동의 증거가 필요하다. 실패를 숨기기 위한 시험 생략·기대 결과 완화는 하지 않는다.
6. [검증결과 양식](../../../기준/양식/검증결과.md)에 실행 ID·환경·코드·계약·입력·예상·실제·판정·증거를 기록한다. 실제 코드 저장소가 요구하는 증거와 진행 기록도 같은 범위로 연결한다. 재시험은 이전 기록을 보존한다.
7. 완료 기준을 충족한 범위만 상태에 반영한다. 일부 메시지나 Mock 시험 통과를 기능 전체·실제 모듈 통합 통과로 확대하지 않는다. [record-work](../record-work/SKILL.md)에 따라 관련 업무 기록을 연결한다.

## 결과

실제 변경 범위, 실행한 검증과 근거, 실패·미실행 이유, 남은 결정·다음 작업을 보고한다. 현재 기능 ID·경로·정책값·시험 명령은 과제계획과 코드 저장소에서 읽으며 이 스킬에 고정하지 않는다.
