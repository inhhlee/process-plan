# 업무 기록 정리

## 필요한 자료

[업무 문서 역할 안내](../../../README.md#document-map)와 [공통 작성 규칙](../../../기준/공통%20작성%20규칙.md)을 적용한다. 관제 업무는 [프로젝트 지침](../../../관제시스템%20과제%20진행/AGENTS.md)과 관련 과제계획·산출물도 확인한다.

요청한 문서에 따라 필요한 기준만 읽는다.

- 일일업무: [빈 양식](../../../기준/양식/일일업무.md)
- 주간보고: [작성 규칙](../../../기준/보고%20작성%20기준.md#weekly-report)
- 변경보고: [작성 규칙](../../../기준/보고%20작성%20기준.md#change-report)
- 시험 결과: [검증결과 양식](../../../기준/양식/검증결과.md)

## 수행 방법

1. 기록할 날짜·기간·프로젝트·과제와 근거를 확인한다. 사용자 보고, 직접 수행한 결과, 예정 작업과 예시를 구분한다. 날짜가 불명확하면 파일 날짜나 완료일을 추정하지 않는다.
2. 요청과 관련된 기존 일일·주간·계획·산출물·시험 결과를 읽는다. 날짜별 통합 일일업무가 있으면 해당 파일을 갱신하고, 없을 때 양식으로 만든다. 같은 날짜에 과제별 일일업무를 중복 생성하지 않는다.
3. 상세 결과는 담당 산출물에 기록한다. 실제 시험은 실행별 검증결과에 근거를 남기고 일일업무에는 수행 범위·남은 작업·링크를 쓴다. 기존 실행의 실패·미실행 기록과 과거 변경 이력을 보존한다.
4. 주간 기록은 해당 기간의 확인된 일일 결과를 목표·계획·진행사항·완료사항으로 요약한다. 기간 뒤쪽 날짜의 실적이나 미정 기한을 채우지 않는다. 완료한 작업을 진행 중 항목과 중복 집계하지 않는다.
5. 영향받는 과제계획·전체일정에는 범위·기한·상태가 바뀐 경우 필요한 요약과 근거를 반영한다. 기록 정리만으로 제품 기능을 완료 처리하지 않는다.
6. 일반 수정은 기존 담당 문서와 필요한 업무 요약에 반영한다. 별도 변경보고가 필요한지는 [보고 작성 기준](../../../기준/보고%20작성%20기준.md#change-report)을 따른다. 보고가 필요하면 기존 방향·변경 위치·전후 내용·이유·결과를 작성하고 주간·일일 기록에는 요약과 링크를 둔다.
7. 피드백과 남은 일은 수정 대상·행동·확인 방법·완료 조건으로 정리한다. 파일·항목 링크, 보고 기간, 완료 근거와 문서 간 상태를 대조한다.

## 결과

반영한 파일과 기록 범위, 확인 근거, 남은 작업을 보고한다. 외부 제출·이메일·메시지 전송은 별도 요청이 있는 경우에만 수행한다.
