# 개발계획 작성·검토

이 저장소에서 사용하는 스킬이다. 아래 링크는 이 파일을 기준으로 해석한다. 기준 문서나 프로젝트 자료가 없으면 실제 위치를 확인하고, 내용을 추정해 새 기준을 만들지 않는다.

## 필요한 자료

- 항상 [개발계획 작성 규칙](../../../기준/개발계획%20작성%20규칙.md), [개발계획서 양식](../../../기준/양식/개발계획서.md), [공통 작성 규칙](../../../기준/공통%20작성%20규칙.md)을 적용한다.
- 기록 위치를 정할 때 [업무 문서 역할 안내](../../../README.md#document-map)를 참조한다.
- 관제 과제는 [프로젝트 지침](../../../관제시스템%20과제%20진행/AGENTS.md)과 대상 과제계획, 관련 요구·규칙·데이터·기능·결정 항목을 확인한다.

## 수행 방법

1. 요청이 신규 작성, 기존 보완, 검토 중 무엇인지 정한다. 기존 계획이 있으면 해당 파일·경로·ID를 유지한다. 검토만 요청받았다면 발견 사항과 근거를 제시한다.
2. 관련 명세와 현재 산출물을 읽어 목표·포함/연계 범위·산출물·선행 조건을 연결한다. 기존 구현을 전제로 계획한다면 실제 코드 저장소의 구조·지침·실행 방법을 확인한다. 위치가 미확인인 단계는 그 상태와 확인 작업을 남긴다.
3. 신규 문서는 빈 양식을 사용하고 기존 문서는 필요한 항목만 갱신한다. 절·하위 제목·표 열·개요 항목·양식 버전은 작성 규칙과 양식에서 가져온다. 기능·단계·행 수는 해당 과제에 맞춘다.
4. 이번 작업을 선택했다면 로드맵에 실제 대상 파일·모듈, 변경 범위, 선행 결정, 시험 입력·예상 결과를 적는다. 실제 경로와 생성 예정 경로를 구분한다. 이번 작업의 성공 조건과 과제 전체 완료 기준을 연결하되 범위를 구분한다.
5. 미정 정책은 결정 항목·선택지·영향·확인 시점에 연결한다. 실습 예제의 기술·단계 수를 기술 선택 근거로 사용하지 않는다. 일정·완료 상태는 확인한 근거로 작성한다.
6. 저장한 본문에서 범위→작업→산출물→시험→완료 기준의 연결, 기존 항목 보존, 미정의 후속 작업과 로컬 링크를 확인한다. HTML이 있는 원본을 수정했다면 [생성 도구 안내](../../../도구/README.md)에 따라 보기본을 갱신하고 본문·표·체크 상태를 대조한다.

## 결과

작성·수정한 계획과 확인 범위, 남은 결정·검토를 보고한다. 실제 수행 기록이 필요한 경우 [record-work](../record-work/SKILL.md)로 연결한다. 구현까지 요청받은 관제 작업은 준비된 계획을 [amr-implement-verify](../amr-implement-verify/SKILL.md)의 입력으로 사용한다.
