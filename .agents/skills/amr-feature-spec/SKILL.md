# 관제 요구 구체화·기능명세 작성·검토

## 필요한 자료

[프로젝트 지침](../../../관제시스템%20과제%20진행/AGENTS.md), [공통 작성 기준](../../../기준/공통%20작성%20규칙.md), [명세 문서 안내](../../../README.md#specifications)를 확인한다. 안내에서 요청과 관련된 요구사항·공통규칙·데이터·기능명세·결정사항·과제계획만 선택해 읽는다. 원문 식별과 제공 상태는 요구사항정의의 자료별 역할을 따른다.

## 부족한 요구를 확인하는 기준

수행 방법의 첫 단계에서 목적·대상 사용자 또는 연계 시스템·주요 동작·포함/제외 범위·관찰 가능한 완료조건을 기존 자료와 대조한다. 요청이 짧다는 이유만으로 질문하거나 새 PRD를 만들지 않는다.

- 기존 자료와 현재 요청에서 확인되는 내용은 다시 묻지 않는다. 관련 없는 미정 정책까지 한꺼번에 해결하려 하지 않는다.
- 이번 범위나 동작·완료 판단을 바꾸는 정보가 부족하면 필요한 질문만 한다. 독립적인 질문은 묶고, 앞선 답에 따라 선택지가 달라지는 질문만 순서대로 확인한다. 선택이 필요한 경우 후보와 영향을 함께 제시한다.
- 사용자가 판단을 맡기거나 질문 생략을 요청하면 확인된 내용과 제안·가정을 구분해 초안을 작성한다. 확인하지 못한 원문·실제 결과를 가정으로 채우지 않는다. 미해결 정책과 후속 확인은 관련 결정 항목에 연결하되, 적용 근거 없이 운영 확정으로 바꾸지 않는다.
- 이미 정해진 임시 계약은 적용 범위 안에서 활용한다. 남은 정책이 이번 요청에 영향을 주지 않으면 후속으로 남기고 가능한 작업을 계속한다.

## 수행 방법

1. 요청이 요구 구체화·작성·보완·검토 중 무엇인지와 관련 기능 ID를 확인한다. 기존 내용과 연결을 읽고 위 기준으로 부족한 정보만 확인한다. 검토만 요청받았다면 수정 없이 문제·근거·영향을 정리한다.
2. 원문 요구·기존 설계·새 제안·사용자 변경을 구분하고 공통 기준의 근거 항목을 기록한다. 원문을 열지 못하거나 위치를 확인하지 못하면 그 범위를 미확인으로 남긴다. 다른 명세의 자기 참조를 원본 근거로 쓰지 않는다.
3. 문서별 담당 내용을 지킨다. 요구·결과물은 요구사항정의, 모듈 공통 기준은 공통규칙, 필드·단위·허용값·Topic·Payload는 공통데이터명세, 기능의 목적·입력·처리·출력·확인 방법은 기능명세에 작성한다. 실제 정책 충돌·선택·근거는 결정사항에 둔다.
4. 기존 ID를 유지하고 R·C·데이터·기능·D·과제계획을 연결한다. 원문의 기능을 분리하거나 새 제안을 추가하는 경우 이유와 영향을 남긴다. 현재 동작이나 예시만으로 원문 요구를 변경하지 않는다.
5. 장비 식별, 상태 전환, Command/ACK, Heartbeat, 재접속, 저장·조회 정책의 의미와 담당 모듈을 대조한다. 입력·필드·단위·허용값·예외·예상 결과가 부족한 항목은 관련 D와 후속 작업으로 연결한다.
6. 과제별 요구·결과물의 누락과 기능별 확인 가능성을 검토한다. 완료조건은 가능한 한 `입력·조건 → 관찰할 결과`로 구체화하고, 개별 과제·통합 시험 및 Mock·대역·실제 모듈 연결의 범위를 구분한다. 확인 방법은 시험 계획이며 실제 결과로 기록하지 않는다.
7. 편집했다면 영향받은 명세·계획의 연결과 ID·상태·근거를 다시 확인한다. 확정되지 않은 정책을 형식 완성을 위해 확정하지 않는다.

## 결과와 저장 범위

- 검토만 또는 화면에만 초안을 요청받았다면 대화에 결과를 제시하고 파일을 생성·수정하지 않는다. 문서 반영을 요청받았다면 기존 담당 문서를 갱신한다. 이미 승인한 문서 수정에 형식적인 재승인을 요구하지 않는다.
- 저장 위치는 사용자의 지정과 기존 문서 구조를 따른다. 같은 요구를 별도 `docs/prd/`에 중복 저장하지 않는다. 별도 PRD를 명시적으로 요청받은 경우에는 기존 명세와의 관계·참조 위치를 분명히 한다.
- 명세 작업 요청만으로 코드 구현이나 제품 시험을 시작하지 않는다. 구현까지 요청받았다면 해당 범위의 명세를 정리한 뒤 [구현·검증 절차](../amr-implement-verify/SKILL.md)로 이어간다.

확인 범위, 발견 사항의 파일·항목, 반영한 내용, 남은 결정·미확인 원문을 보고한다. 실제 동작 검증을 수행하지 않았다면 명세 검토 결과와 구분한다. 최신 진도는 일정·계획·검증결과를 참조하며 이 스킬에 저장하지 않는다.
