이 계획은 프로젝트의 과제2를 완료하기 위한 목표·작업 순서·산출물·확인 기준을 정리한다. 2026-10-20 사용자는 과제1의 남은 개발을 보류하고 과제2를 먼저 진행하도록 요청했다. 10월 21일 우선 목표는 설정 로드 → AMR 1대 생성 → 경로 이동·도착 확인이다. 이 결과를 확보한 뒤 Heartbeat·Telemetry를 기존 과제1 수신 콘솔에 연결한다. 과제2 개발은 미착수·실행 미검증이며 과제1의 전체 완료나 책임님의 검토·납품 일정 승인을 뜻하지 않는다.

2배경과 목적

이동·상태 변경·알람 발생·명령 응답을 제공하는 독립 시뮬레이터를 구성하고, 수량·초기 좌표·속도·이동 경로·장애 시나리오를 설정 파일로 바꾸어 시험할 수 있도록 한다.

3용어 설명

용어 쉬운 설명
가상 AMR 실제 로봇 대신 위치·상태·알람·명령 응답을 만들어 주는 시험 프로그램이다.
Telemetry AMR의 위치·속도·상태 등 현재 정보를 전달하는 데이터다.
State / Alarm 운행 상태와 장애 알림이다. 상태 변화와 알람의 관계는 D-05에서 정한다.
Command / ACK AMR에 보내는 동작 요청과 응답이다. 명령과 응답은 같은 요청 ID로 연결한다.
시나리오 설정 수량·초기 좌표·속도·경로·장애 조건을 코드 수정 없이 바꾸기 위한 입력이다.

4기능 범위

포함하는 기능

기능 ID 기능명 제공할 동작
AMR-01 설정 로드와 AMR 생성 설정 파일로 독립 시뮬레이터의 시험 조건을 구성한다.
AMR-02 Command 수신과 동작 수행 MOVE·STOP·RESET 후보 명령을 시뮬레이션한다.
AMR-03 State와 Alarm 관리 설정한 장애 조건에 따른 알람 발생·해제와 운행 상태 변화를 생성한다.
AMR-04 명령 처리 결과와 ACK 생성 수신한 요청에 대응하는 수행 결과를 반환한다.
AMR-05 시뮬레이션 데이터 생성과 송신 시뮬레이션 결과와 생존 정보를 공통 계약에 따라 전달한다.

기능의 목적·입력·처리·출력은 기능명세에서 관리한다. 이 계획에는 수행할 작업과 확인할 결과를 기록한다.

6개발 로드맵

선행 조건과 단계 흐름

  • 공통 좌표·상태·메시지 계약을 공유한다. 과제1 전체 완료는 이번 독립 실행본의 선행 조건이 아니다. 실제 Core·GUI 없이 먼저 이동을 확인한다.
  • 현재 C:\amr-control-system-demo에는 통신 라이브러리·콘솔·시험 프로젝트가 있고 Amr.Simulator와 전용 시험 프로젝트는 없다. 기존 수신·검사·큐는 송신 연동 시 활용하며, AMR 발행 기능은 새로 추가해야 한다.

전체 작업 순서

개발 상태는 미착수이며 첫 작업은 2026-10-21 착수 예정이다. 아래는 첫 실행본을 우선한 순서로, 원문의 이동·상태·알람·명령 응답과 다섯 설정 항목은 모두 유지한다.

순서 관련 항목 수행할 작업 완료 확인 조건
1 AMR-01 D-02·D-12의 단일 AMR용 설정·오류 처리만 먼저 정리하고 로드·생성한다. ID·초기 좌표·속도·경로 변경이 코드 수정 없이 생성 결과에 반영된다.
2 AMR-02 일부 최소 이동·도착 기준을 정리하고 설정 경로 이동을 구현한다. 경과 시간에 따른 좌표 갱신·도착·정지를 Broker 없이 재현한다. 명령 제어 완료와 구분한다.
3 AMR-05 일부 기존 계약으로 Heartbeat·Telemetry를 생성·송신한다. 기존 과제1 콘솔에서 ID·시각·좌표·속도·State를 검사·수신한다.
4 AMR-01, AMR-03 수량·장애 시나리오 설정을 확장하고 State·Alarm·명령 허용표를 정리한다. 다섯 설정 항목과 장애 발생·해제·복구의 예상 결과가 구분된다.
5 AMR-02~04 MOVE·STOP·RESET 수신·동작·거부·복구와 CommandId를 보존하는 ACK를 구현한다. D-05·D-07 적용 내용을 기록하고 정상·거부·실패 응답이 원래 요청에 연결된다.
6 AMR-05 Alarm·ACK 이벤트 송신과 다중 AMR 송신을 확인한다. 네 유형이 기존 계약 검증을 통과하고 AMR별 데이터가 섞이지 않는다.
7 AMR-01~05 독립 실행과 설정 변경·명령·장애 시험 결과를 정리한다. 사용 설정, 예상·실제 상태와 메시지를 근거로 남긴다.

  • 첫 구현 전에 D-02·D-05·D-12에서 설정 형식·오류 처리, 경유점 이동·도착 기준, 갱신 주기와 이동 중/도착 상태만 정리한다. JSON·직선 경유점 이동은 실습 제안이며 원문 확정값이 아니다. MOVE·STOP·RESET 허용표·장애·ACK 의미는 해당 후속 단계 전에 결정한다.
  • 기존 개발 단위 m·m/s와 Unix 밀리초·메시지 필드는 공통데이터명세를 따른다. 과거 TestClient의 미구현 응답을 이동 완료 ACK로 사용하지 않는다.

이번 작업 시험

아래는 첫 실행본의 예정 확인이며 현재 전부 미검증이다. 예제 숫자는 시험 입력이며 운영 정책값이 아니다. 첫 다섯 항목을 내일 우선하고 F06은 송신 확장 시 수행한다.

시험 ID 입력·조건 성공 기준 실패 판단
AMR2-F01 단일 ID·초기 좌표·양수 속도·경로가 있는 설정 로드 AMR 1대와 설정값을 실행 출력에서 식별 코드에 고정한 값으로 생성되거나 설정과 불일치
AMR2-F02 같은 실행 방법에서 초기 좌표·속도·경로만 바꾸어 재실행 코드 변경 없이 초기값·이동 결과 변경 변경 설정이 반영되지 않음
AMR2-F03 직선 경유점 안을 채택한 경우 (0,0)→(1,0), 1m/s, 경과 0.5초 계산 위치 (0.5,0). 허용 오차는 착수 때 D-02에 기록 정한 허용 오차 초과·반대 방향·실제 대기에 의존한 불안정 판정
AMR2-F04 같은 경로에 도착하고 추가 갱신 목표 좌표에서 정지, 목표를 지나쳐 누적 이동하지 않음 도착 뒤에도 좌표·이동이 계속됨
AMR2-F05 중복 ID 또는 잘못된 좌표·음수 속도 등 선택한 오류 설정 D-12에 정한 기준으로 시작 전 거부·이유 출력 잘못된 설정으로 실행·이유 없는 무시
AMR2-F06 후속 송신 단계에서 새 Client ID·실제 Broker·기존 과제1 수신 콘솔 Heartbeat·Telemetry 검사 통과, 같은 AMR과 변경 좌표 수신·정상 종료 불량 Payload·대상 혼합·수신 누락·종료 불가

상세 실행 절차

2026-10-21 예정 절차다. 아래 파일·실행 옵션은 생성 전이며 현재 사용 가능한 명령으로 보고하지 않는다.

  1. 최신 develop·기존 변경·같은 작업의 Issue를 확인한다. 기존 AGENTS.md 변경을 보존하고 과제1 #6을 이번 작업에 섞지 않는다.
  2. D-02·D-05·D-12의 첫 실행본에 필요한 항목과 예제 설정을 먼저 정리하고 독립 콘솔·시험 프로젝트를 준비한다. 생성 후 빌드 명령·실행 옵션을 코드 README에 실제 경로로 기록한다.
  3. 설정 A를 로드해 ID·초기값을 확인하고, 설정 B로 초기 좌표·속도·경로만 바꾸어 재실행한다. 잘못된 설정의 거부 결과도 남긴다.
  4. 경과 시간을 제어해 이동·도착 계산을 시험하고 실제 콘솔 실행의 좌표 변화·종료를 확인한다. AMR2-F01~05와 코드·설정 버전을 evidence/AMR/<새 실행ID>/에 연결한다.
  5. 우선 결과를 확보한 뒤 MQTT 송신 확장에 착수한다. 송신 Payload는 기존 계약 필드로 구성하고 수신 전용 ReceivedAtUtc를 포함한 모델을 그대로 직렬화하지 않는다. Broker 주소·포트·기존 서비스 상태를 확인한 뒤 기존 수신 콘솔에서 F06을 수행한다.
  6. 업무 종료 때 수행 단계·예상/실제·막힌 점·미검증 범위·다음 작업을 10/21 일일업무에 기록한다. 이동 확인까지 끝났어도 MQTT·다중 AMR·장애·명령/ACK는 실제 결과에 따라 별도로 남긴다.
