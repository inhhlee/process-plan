COM-01 AMR ID가 다른 정상 메시지와 대상별 Command 정의된 Topic·방향·대상으로 수신·전달된다.

새 실습은 승인한 실제 Issue URL과 C:\process-plan의 최신 문서를 코드 채팅에 전달한다. 정상 접속·종료 #8은 A1 PR #12 반영 후 A2 중간 결과 → A3 최종 수명주기 순서로 수행했다. COM01-C #23은 PR #24의 develop 병합(e207614)을 확인하고 완료조건 5개를 체크해 종료했다. 자동시험 547건·실제 MQTT 정상/종료/새 세션·Broker 중단을 확인했다. 최종 검증결과. 실제 MQTT 과부하·장시간 부하·네트워크 무응답은 미검증이다. #9용 별도 브랜치·PR은 만들지 않는다. 실제 인자·명령은 코드 README에 작성한다. 시험 대역·실제 Broker·무응답 도구의 범위를 구분해 evidence/<기능ID>/<실행ID>/에 근거를 남긴다. #4에서 정상 접속·종료 전체를 확인하고 최종 과제 근거는 TASK1-V에서 연결한다. 이번 구현 요청에서 수행한 자동시험·실제 MQTT 결과는 위 실행 근거에 기록했다.

아래는 Heartbeat 회귀를 선택했을 때 실행할 절차다. 이번 문서 정리에서 수행한 시험 결과가 아니다. 정상 메시지는 id, ts, status: "OK"를 포함하는 계약·JSON 예제를 사용한다. 다음 코드 작업에서는 표준 기준선 확인 후 선택한 범위의 절차를 수행한다.

선행 조건은 SDK·Docker·기존 amr-mosquitto 준비, 다른 AMR_001 발행 실험과 혼동되지 않는 실행 시간대, 두 개의 PowerShell 터미널이다. 다른 프로세스를 임의로 종료하지 않는다. MQTT Explorer는 필요하지 않으며 컨테이너에 있는 mosquitto_pub을 사용한다. -s, -V, -q, -t 옵션은 2026-10-05 준비 당시 확인한 절차를 유지하며 실제 착수 때 현재 환경과 대조한다.

터미널 A — 관제 수신을 먼저 시작한다.

Set-Location C:\practice
.\init.cmd check
# Broker가 준비되지 않은 경우에만 실행
.\init.cmd broker
.\init.cmd start -Heartbeat

Connected, Subscribed: amr/+/heartbeat, amr/+/telemetry, amr/+/alarm, amr/+/ack를 확인한 뒤 터미널 A를 유지한다. start만 실행하면 연결 전용이므로 수신 시험에는 -Heartbeat가 필요하다. 이 모드는 DN-10 감시도 켜므로 발행을 멈추면 Timeout/Recovered 알림이 섞일 수 있다. HB-01~06은 Received·Rejected를 판정하며 이 알림만으로 COM-02 재검증을 완료하지 않는다. 연결 주소 127.0.0.1:1883와 실행별 evidence 경로도 기록한다.

터미널 B — 기존 시험 클라이언트의 정상 발행을 확인한다.

Set-Location C:\practice
dotnet run --project .\src\Amr.TestClient -- AMR_001

발행자가 연결된 뒤 10초 이내에 최소 3건의 발행·수신이 대응하는지 ID·ts로 비교한다. 이는 로컬 기능 확인을 위한 관찰 조건이며 전송 보장이나 성능 기준이 아니다. 관찰 후 B의 발행자를 Ctrl+C로 정상 종료한다. A의 수신자는 계속 유지한다.

터미널 B — 고정 예제와 오류 예제를 한 건씩 발행한다.

$exampleDir = 'C:\process-plan\관제시스템 과제 진행\과제1\산출물\COM-01_Heartbeat_예제'
Get-Content -Raw -LiteralPath (Join-Path $exampleDir 'heartbeat-valid.json') | docker exec -i amr-mosquitto mosquitto_pub -h 127.0.0.1 -p 1883 -V mqttv5 -q 0 -t amr/AMR_001/heartbeat -s

출력은 A에서 확인한다. 같은 명령의 파일명을 순서대로 heartbeat-missing-ts.json, heartbeat-id-mismatch.json, 마지막으로 다시 heartbeat-valid.json으로 바꾸어 실행한다. 각 입력 직후 기대 출력을 확인한 뒤 다음 입력을 보낸다. -r을 사용하지 않아 Retain=false를 유지한다. 명령의 비정상 종료나 수신 결과 누락은 기록하며, 발행 종료 코드만으로 성공 판정하지 않는다.

한 건 발행 시험은 명령 완료 후 최대 5초 관찰하여 해당 결과를 기록한다. 정상 발행자를 중지하고 한 건씩 시험해 출력의 대응을 확인한다. 여러 발행자가 섞여 판정할 수 없으면 통과로 기록하지 않고 원인을 남긴다.
