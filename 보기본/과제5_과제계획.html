이 계획은 프로젝트의 과제5를 완료하기 위한 목표·작업 순서·산출물·확인 기준을 정리한다. 계획과 예상 결과를 작성한 상태이며 이 과제의 실제 구현·시험 결과는 이 문서에서 아직 확인하지 않았다. 기존 코드의 재사용 범위는 착수 전에 대조한다. 아래 작업 순서와 시험 항목은 요구사항·공통 규칙·데이터·기능명세를 기준으로 제안한 초기 계획이다.

2배경과 목적

과제1~4의 구성요소와 SQLite를 연결하여 가상 AMR 기반 기초 관제 시스템 실행본을 구성하고, 전체 경로의 동작을 시나리오로 검증한다.

3용어 설명

용어 쉬운 설명
통합 검증 각 모듈을 실제로 연결한 전체 경로의 동작을 확인하는 시험이다.
시나리오 입력·조건·절차와 예상 결과를 정하여 반복할 수 있게 만든 시험 흐름이다.
계약 버전 연결한 모듈이 공통으로 적용한 데이터·메시지·인터페이스 정의의 판이다.
재현 절차 다른 사람이 같은 설정과 순서로 시험을 다시 수행할 수 있게 남기는 방법이다.
ACK / History 명령에 대한 응답과 업무 이력이다. 요청부터 응답·표시·저장까지 연결해서 확인한다.

4기능 범위

포함하는 기능

기능 ID 기능명 제공할 동작
INT-01 정상 운행과 표시 검증 AMR 데이터가 통신·Core·GUI까지 일관되게 연결되는지 확인한다.
INT-02 Command 전체 흐름 검증 화면 요청과 실제 시뮬레이터 결과가 같은 요청으로 연결되는지 확인한다.
INT-03 Alarm 발생과 해제 검증 장애 시나리오의 알람·운행 상태·화면·이력이 연결되는지 확인한다.
INT-04 통신 이상과 복구 검증 Broker 장애와 개별 AMR 중단을 구분하고 복구 후 동작을 확인한다.

기능의 목적·입력·처리·출력은 기능명세에서 관리한다. 이 계획에는 수행할 작업과 확인할 결과를 기록한다.

제외·연계 범위

다음은 다른 과제의 담당 범위를 구분한 것이며 프로젝트 전체에서 제외한다는 뜻이 아니다.

항목 이유·담당 과제
각 모듈의 개별 기능 개발·시험 과제1~4의 담당 범위. 통합 중 발견한 결함은 해당 과제에 연결하여 수정·재시험한다.

공통 저장소와 기본 환경은 개발환경 및 코드 저장 위치에서 확인한다. 아래는 이 과제의 구성과 선택 상태이며, 해당 기능의 라이브러리·재사용 범위·실행 가능 여부는 착수 전에 확인한다.

전체 작업 순서

이 계획의 개발 상태는 미착수로 유지하며 작업별 예정 기한은 미정이다. 기존 코드의 해당 과제 적용 범위를 확인한 뒤 실제 상태를 갱신한다. 필요한 설계 결정부터 정리하고 결정 내용을 적용한 버전으로 시험한다.

순서 관련 항목 수행할 작업 완료 확인 조건

3 INT-01 정상 운행과 설정 변경의 전체 흐름을 검증한다. AMR 데이터가 통신·Core·GUI에 같은 장비·좌표·상태로 반영된다.

6 INT-04 개별 AMR 중단과 Broker 장애·복구를 각각 검증한다. 장애 구분·Log·재접속·재구독·수신 재개와 대기 명령 처리를 확인한다.
7 INT-01~04 통합 결과·재현 절차·미해결 문제와 수정 후 재시험을 정리한다. 최종 실행본과 실제 결과·판정·근거를 연결한다.

7완료 기준

과제 전체 완료 체크

  • 과제1~4와 SQLite가 연결된 기초 관제 시스템 실행본을 제공한다.
  • 정상 운행·명령·알람·통신 이상 시나리오를 실제로 수행한다.
  • 설정·계약 버전·실행 순서·예상 결과·실제 결과·판정을 기록한다.
  • 실패한 시험은 해결·재시험 결과 또는 미해결 영향 범위를 명시한다.
  • 실행본과 재현 절차를 연결하고 검증 결과를 근거로 완료 여부를 판단한다.

위 체크는 실제 결과를 확인한 뒤 표시한다. 계획 초안 작성 완료와 과제 개발 완료를 구분한다.

전체 시험 계획

다음 표는 예상 확인 결과이다. 현재 모든 항목의 실제 결과와 판정은 미검증이다.

기능 시험 조건 예상 확인 결과
INT-01 정상 운행과 설정 변경 장비 ID·위치·속도·State가 생성·수신·관리·표시 단계에서 일치한다.
INT-02 정상·거부 명령과 정책에 따른 응답 예외 같은 요청 ID와 대상의 수행·응답·화면·저장 결과가 연결된다.
INT-03 장애 발생·해제·RESET 조건 운행 상태·알람·명령 제한·복구·발생/해제 이력이 결정한 기준을 따른다.
INT-04 Broker가 살아 있는 개별 AMR 중단 다른 AMR과 구분하여 감시·표시하고 운행 상태를 임의로 바꾸지 않는다.
INT-04 Broker 종료·재시작과 대기 중 명령 재접속·구독·송수신이 복구되고 대기 명령의 처리·중복 수행 여부를 확인한다.
INT-01~04, COM-04 비정상 메시지 뒤 정상 메시지 비정상 입력이 업무 상태에 반영되지 않고 이후 정상 흐름이 유지된다.

실행 후에는 사용 설정·계약 버전, 입력, 절차, 예상 결과, 실제 결과, 판정 및 Log·화면·DB 등 근거를 검증 결과에 작성한다. 미정 정책에 의존하는 시험은 해당 결정 항목과 적용 값을 함께 기록한다.
