## 피드백 및 반영할 내용

- 감시 수명은 MQTT 연결과 함께 Communication에서 소유하고 Core의 업무 상태와 GUI 표시를 분리한다. 앞선 단일 분리에서는 다중 AMR·자동 재접속을 도입하지 않았다. 이후 후속은 두 AMR·Core 정책으로 범위를 확장했고 자동 재접속은 계속 제외한다.
- 최초 using 누락 빌드·NuGet 조회 경고·폴더 보기 F5 오류·시험 Broker 중단/임시 포트 변경·콘솔 시험 도구 경로 오류를 보존하고 수정/환경 분리 뒤 성공 근거를 연결했다.
- 최종 타이머 시작 중 Broker 단절 경합을 수정 전 재현하고 시작 가드를 보강했다. 최초 타이머 예외 주입 대역의 .NET 최종화 오류/시험 호스트 중단은 보존하고 최종1116건 재실행만 성공으로 집계한다. 실제 콘솔도 최종 가드가 있는 실행 파일로 재검증했다.
- 별도 시험 GUI3개는 UI 사용자 입력 보호로 창 닫힘이 차단되어 소유 프로세스로 정리했다. 이번 정상 창 닫힘 검증으로 집계하지 않는다. F5·콘솔·호스트/세션의 종료 근거와 구분한다.

- 후속 두 AMR: 수신/검사·형식화 통지 순서를 통신에서 관리하고 Core에서 이전 세션/중복 관측을 배제한다. 무응답은 해당 미션만 보류하며 복구 후 명시 재개한다. 관제 보류는 차량 물리 정지가 아니다.
- 첫 실제 실행의 MQTT ClientId 충돌을 수신 연결의 독립 설정으로 수정했다. Broker 단절 뒤 미션 보류가 취소로 덮인 첫 실패를 보존하고 제어 API/GUI 차단으로 보강했다. 첫 GUI 최소 크기 시험 실패도 보존하며 최종1141건만 최신 성공으로 집계한다.
- 최종 전용 시험 자원은 모두 정리했고 기존7컨테이너·Visual Studio와 Git 참조를 유지했다. 새 Fleet 네이티브 F5/네이티브 재개 버튼 클릭·이번 정상 창 닫힘은 성공으로 집계하지 않는다.
