## 1. 기존 방향

### 2026-10-05 최초 적용

과제별로 목표·범위, 작업 순서, 산출물, 시험 계획, 완료 기준, 다음 작업의 6개 절을 사용했다. 기능 ID와 R·C·D 연결, 개발 미착수·실행 미검증 상태는 기록되어 있었다. 용어 설명·기술 선택 상태·과제 간 범위 구분과 공통 HTML 보기 형식은 별도 양식으로 정해져 있지 않았다.

### 2026-10-06 추가 통일

8개 대제목은 같았으나, 빈 양식과 과제계획의 기능 범위·산출물 표가 달랐다. 과제1의 작업 단위 표는 독자적인 열을 사용했고, 과제2~5는 작업 단위 표가 없었다. 과제1은 상세 시험 절차가 전체 완료 기준보다 먼저 나와 같은 위치에서 같은 내용을 찾기 어려웠다.

## 3. 변경 결과

### 2026-10-05 최초 적용 당시 결과

- 문서와 보기본 반영: 완료.
- 형식·내용 보존 확인: 과제1~5 모두 8개 절이다. 기존 본문의 작업·기능 ID·산출물·시험 계획·완료 기준을 줄 단위로 대조하여 보존을 확인했다. 각 과제의 완료 체크 5개는 모두 미완료 상태다.
- 링크 확인: 작업 폴더의 Markdown 문서에서 로컬 파일·문서 항목 링크 562개를 검사했고 대상 파일·제목 누락은 발견하지 않았다. 원문 내용의 기술적 정확성 검토와는 구분한다.
- HTML 확인: 빈 양식과 과제1~5의 보기본 6개를 실제 브라우저로 열었다. 각 보기본의 8개 절·목차, 빈 표 셀·완료 체크 상태와 1440px/390px 화면의 페이지 가로 넘침을 확인했다. 좁은 화면의 넓은 표는 표 영역 안에서 가로 스크롤한다. 과제1의 표지·로드맵·완료 기준·좁은 화면을 이미지로 확인하고 로드맵 첫 열의 줄바꿈을 보정했다.
- 설계 상태: 기존 미정·제안·임시 채택 상태 유지. 이번 요청은 양식 채택 근거이며 상세 기술·정책 결정 근거가 아니다.
- 사용자 내용 검토: 대기. Agent의 형식 확인과 구분한다.
- 관제 프로그램 개발: 미착수. 실행 검증: 미검증.
- 다음 작업: 과제1의 D-03~D-04에서 첫 송수신에 필요한 메시지·시간 계약을 정리하고, 실제 코드 위치·개발환경을 확인하여 기능별 작업 단위를 채운다.

참고 자료와 페이지, PDF의 8개 구성과 ZIP의 개요+7개 절을 대응시킨 이유는 [개발계획 작성 규칙의 참고와 적용 해석](../../기준/개발계획%20작성%20규칙.md#7-참고와-적용-해석)에 기록했다. 원본 PDF·ZIP은 수정하지 않았다.

### 2026-10-06 추가 통일 결과

- 반영: 빈 양식·작성 규칙·과제1~5·AGENTS·역할 안내 수정, HTML 보기본 6개 재생성 완료.
- 형식: 6개 원본 모두 8개 절·13개 하위 제목·11개 표의 열·문서 개요 26개 항목과 양식 버전 v1.1 일치.
- 내용 보존: 기존 기능 목록 25개, 예정 산출물 20개, 전체 작업 순서 36행, 전체 시험 계획 30행을 대조했다. 과제1의 HB-01~06과 실행 명령 3개 블록, 전체 완료 체크 25개·이번 작업 체크 3개의 내용과 미완료 상태를 유지했다.
- 링크: 수정한 Markdown 11개에서 로컬 파일·항목 링크 257개, 작업 폴더의 Markdown에서 과제계획 항목을 가리키는 링크 21개를 확인했다. 파일·항목 누락 없음.
- HTML: 보기본 6개를 실제 브라우저로 열어 13개 하위 제목·11개 표·빈 표 셀 없음·완료 체크 미표시를 확인했다. 390px 화면 설정(본문 너비 375px)에서 6개 모두 페이지 가로 넘침이 없고, 넓은 표는 표 안에서 가로 스크롤한다. 과제1·2의 기본 화면(본문 너비 1265px)도 가로 넘침이 없었다. 과제1 로드맵·좁은 화면과 과제2 로드맵을 화면으로 확인했다.
- 확인 범위: 문서 구조·연결·내용 보존과 보기본 표시 확인이다. 상세 설계의 정확성이나 제품 동작 검증 결과를 뜻하지 않는다.
- 기능 상태: 과제1은 기존 부분 구현 진행 중, 과제2~5는 문서의 미착수·미검증 상태 유지. 이번 작업에서 제품 코드 수정과 MQTT 재시험은 수행하지 않았다.
- 남은 사용자 검토: 정리된 계획 내용 검토. 상세 설계 미정·임시 기준은 해당 D 항목에서 계속 관리한다.
- 다음 실제 작업: 과제1의 기존 COM-01 Heartbeat 경로를 HB-01~06으로 확인하고 실패한 부분을 보완한다.
