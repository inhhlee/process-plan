## 1. 기존 방향

과제1의 최종 요구는 MQTT 접속 관리·송수신·Heartbeat·메시지 검사·명령/응답·재접속과 콘솔 시험 결과물이다. [R-04](../../관제시스템%20과제%20진행/명세/요구사항정의.md#r-04)와 COM-01~06은 유지한다.

이전 준비 문서는 Heartbeat 최초 송수신과 수신 계약 v1을 기준으로 작성되어 현재 채택 계약·구현 상태와 차이가 있었다. 이번에는 코드 동작만으로 요구를 바꾸지 않고 [기능 추적기의 설계 결정](<C:/practice/feature_list.json>), [수신 계약 v3](<C:/practice/src/Amr.Communication/Validation/CONTRACT.md>), [Command 계약 v1](<C:/practice/src/Amr.Communication/Command/CONTRACT.md>), [감시 계약](<C:/practice/src/Amr.Communication/Monitoring/CONTRACT.md>), [진행 로그](<C:/practice/claude-progress.md>)와 기존 증거를 읽어 적용 범위를 확인했다.

책임님 PDF·요구사항 HWP는 현재 문서에 연결된 경로에 없어 원문을 재판독하지 않았다. 코드 저장소의 PDF 인용·과거 검토 기록은 기존 결정의 근거로만 사용하며 이번 원문 직접 확인으로 격상하지 않는다.

## 3. 변경 결과

문서 반영 후 확인 결과는 다음과 같다. 본 보고서의 문서·형식 검사를 제품 동작 시험으로 사용하지 않는다.

- 기준 연결: D-01~12, R-01~07, C-01~11과 기존 25개 기능 ID 유지. 원문 요구인 자동 재접속을 삭제하지 않음.
- 기존 기록: 2026-10-05 환경 점검의 코드 버전·301개 테스트 및 당시 결과를 보존. 이번 확인은 기존 S024 증거를 읽은 것이며 오늘의 실행 결과가 아님.
- 문서 확인: 변경 문서의 내부 파일·항목 링크 누락 없음. 기존 외부 경로의 PDF·HWP 및 과거 개인 스킬 경로는 미확인으로 보존하고 새 누락 링크는 없음. JSON 3개 파싱과 필드 대조 통과; 기존 값은 그대로이고 status=OK만 추가하여 각 오류의 의도를 유지했다.
- 형식·보기본: 생성 도구의 6개 원본 형식 검사 통과. 과제1의 8개 절·13개 하위 제목·11개 표·개요 26개 항목과 미완료 체크 8개를 유지하고 HTML에 반영했다. 레이아웃 변경이 없어 새 브라우저 화면 검사는 하지 않았다.
- 변경 범위: 이번 작업 직전 사본과 대조하여 기존 파일 15개 수정·변경보고 1개 추가, 나머지 37개 파일 동일. 과제2~5 원본·보기본, 요구사항정의, README·AGENTS·SKILL, 기존 실행 검증결과는 그대로다. Git 공백 검사 통과.
- 추적기 확인: 기존 검증 도구로 5개 기능·37개 검증 항목의 구조·증거 경로 검사 통과. 증거 내용의 재실행·현재 제품 동작 통과를 의미하지 않는다. 코드 저장소의 작업 트리는 변경 없음.
- 제품 상태: 코드 저장소의 COM-01 rev4·COM-02 rev2·COM-03 rev2·COM-04 rev4 passing, COM-05 rev1 not_started를 그대로 참조. 코드 추적기는 5개 기능·37개 검증 항목이며 문서의 COM-06과 구분한다.
- 실제 실행: 제품 빌드·자동 테스트·MQTT 송수신·GUI 시연·GitHub Issue/PR 생성은 미실행.

남은 결정은 실제 Core의 CommandId 생성·전체 매핑, 업무 ACK 예외, 운영 감시·최종 Offline, 자동 재접속·대기 명령 정책이다. 각 기능 착수 시 필요한 범위만 확인한다. 기존 개발용 임시 결정을 외부 호환성·운영 확정으로 확대하지 않는다. 정상 화면 시연 우선은 [기존 개발 순서](<C:/practice/docs/full/assignment_mapping.md>)를 연결한 것이며 사수의 납품 순서 변경 승인은 별도 확인 대상이다.
